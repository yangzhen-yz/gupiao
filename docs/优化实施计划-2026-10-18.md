## 4. 第1批：周期调度线上化（11-02 起，前提：影子结论支持）

### P0-2 周期 → 模式调度（预估 L，2～3天）

**目标**：情绪周期从「仓位旋钮」升级为「选股开关」；「空仓」成为正式输出。阈值已按 1094 口径重跑校准。

**改动点**：
1. `app/config.py` 新增（热加载生效）：
   ```python
   RECOMMEND_MIN_SCORE_BASE = 60                      # 原 recommend.py:1036 硬编码上移
   CYCLE_MAX_RECOMMEND = {'冰点':1,'退潮':1,'分歧':2,'回暖':3,'发酵':3,'高潮':2}
   CYCLE_ALLOW_EMPTY = ('退潮','高潮')                 # 这两个周期允许 0 只推荐
   CYCLE_EXTREME_HOT_LIMIT_UPS = 120                  # 涨停>120家=极热档（模式级规则，见下）
   ```
2. `recommend.py` 主链路（`auto_generate_recommendations_task`，1036 行附近）：
   - `gate = cycle_gate(await get_sentiment())`（影子已有同款调用，直接复用）；
   - 线上 min_score = `max(RECOMMEND_MIN_SCORE_BASE, gate['minScore'] if gate['vetoEnabled'] else base)`；
   - 角色否决：`bsp['stockType']` 命中 `gate['vetoRoles']` 的角色不进 Top3（与影子同口径）；
   - 不追高：`not gate['allowChase']` 且涨幅≥5% 的票不进 Top3；
   - 推荐数上限改 `CYCLE_MAX_RECOMMEND[cycle]`，不足则**不补足**（删掉 1136 行「不足3只从剩余补足」的逻辑，改为允许 N<3）；
   - 空仓输出：0 只时写一条哨兵记录 `symbol='CASH'`、`name='空仓观望'`、`reason='{cycle}·{note}'`、`buy_price=''`（复盘 `_load_all_recommendations` 对非数值 buy_price 自动跳过，安全）；
   - **极热模式级规则（非一刀切）**：涨停 >120 家且非 stale → 禁低吸/追高形态，但**打板保留**（1094口径：极热档全体买入 42.6%/-0.28% 最差，但封板接力仍 67.1%/+2.06%、957样本），打板仅限主线早盘板且当日最多1只；无主线时空仓哨兵。
3. 前端：`TabRecommend.vue` 顶部常驻「今日模式」横幅（cycle + note + 推荐数上限 + 模式禁令清单），空仓时渲染空仓卡片（不显示凑数票）。
4. 影子机制保留但降级为「日常监控」：影子与线上口径将趋同，其价值转为「线上化后的持续回归对照」。

**验收**：连续 5 个交易日，推荐数/门槛随 cycle 变化且日志有据；退潮日出现空仓哨兵；极热日推荐 ≤1 且全为打板；`recommend_flow_selftest.py` 增加 gate 消费用例并通过。
**回滚**：`RECOMMEND_MIN_SCORE_BASE` 改回 60 + `CYCLE_MAX_RECOMMEND` 全设 3 + 恢复补足逻辑（用配置开关 `RECOMMEND_CYCLE_SCHEDULE_ENABLED=False` 一键关闭，代码保留）。

### P0-3 主线消费（预估 M，约1天）

**目标**：leadSectors 从展示数据变成选股输入——「只做主线内的票」落地为加成而非硬过滤（避免弱市主线噪声）。

**改动点**：
1. `sentiment.py` `_lead_sectors` 输出增加 `stage` 字段（启动/发酵/高潮/退潮，依据：maxLianban + tierCount + promotionRate，如 `maxLianban≥3 and tierCount≥2 → 发酵以上`）；
2. `recommend.py` 候选循环：命中 leadSectors 前两名（`hybk` 与 `primary_tag`/industry 匹配）的票，评分后加 `RECOMMEND_MAINLINE_BONUS=+3`；命中「退潮阶段主线」的不加成也不否决；
3. `daily_recommendations` 该票 `reason` 追加「主线：{sector}（{stage}）」；前端推荐卡显示主线徽章。

**验收**：主线票的加分在日志可见；人工抽查 3 个交易日的主线判定与当日涨停池 hybk 一致。
**回滚**：bonus 设为 0 即关闭；stage 字段纯展示。

## 5. 第2批：止损重构与账户熔断

### P1-1 逻辑止损 + 时间止损 + 连板期限规则（预估 M，约1天）

**目标**：统一三套并存的振幅止损（risk_control ×1.5钳[4,12] / position 分档6/8/10/12 / review 明日计划 ×0.8钳[4,8]），并把低波档 4～6% 的「噪音止损」（低于趋势票 10日最大不利中位 -5.36%，会被系统性洗掉）换成证伪驱动。注意：高波档 10～12% 并不窄，问题在别处（触发即重伤），不要一刀切抬高所有档位。

**改动点**：
1. `review.py` `_build_tomorrow_plan()`（明日买入计划）与 `risk_control.py` `calc_risk_control()` 同步增加两种止损：
   - **逻辑止损**：低吸票 = 跌破 MA20 收盘 或 买入形态破坏（放量滞涨/量价背离命中，即 `pattern.py` 负向形态）；打板票 = 次日炸板未回封；
   - **时间止损**：低吸票 T+3 涨幅 <1% 且未触发止盈 → 了结（动量票拿不过第3天的数据结论工程化）；
   - **连板期限规则**：`daily_recommendations`/趋势池中连板≥2的票强制归打板模式，禁止以趋势名义持仓超过次日（5日大面 74.8% 的尾部用期限规则砍）；
   - 原振幅止损降级为「兜底下限」：逻辑/时间止损位与振幅止损位**取较近者**，并在 `stopLossSrc` 字段标注来源（`logic`/`time`/`amplitude`）。
2. 前端持仓页 `TabPosition.vue` 的止损行显示来源标签，让用户知道这条线为什么在这里。

**验收**：明日买入计划的 stopLoss 从「只有百分比」变为「价+来源」；历史回放 10 月推荐，逻辑止损触发次数 < 振幅止损（证明不再被噪音洗）；连板票过夜持仓被期限规则拦截。
**回滚**：`RISK_STOP_LOGIC_ENABLED=False` 恢复纯振幅口径。

### P2-1 账户回撤熔断 + 机会评级（预估 M，约1天）

**目标**：把「慢就是快」机制化——单票止损管不了的连续小亏，由账户级规则管。

**改动点**：
1. 新增 `services/portfolio/drawdown_guard.py`：
   - 数据源：`portfolio/trade_sim.py` 的模拟账户流水（无实盘账户则用模拟盘口径，前端标注）；
   - 规则（配置化）：`DRAWDOWN_MONTHLY_LIMIT=-8`（月回撤≥8% → 次日总仓上限减半）、`DRAWDOWN_CONSEC_LOSS=3`（连亏3笔 → 3个交易日内禁止 `mode=daban` 的票）；
   - 熔断状态落 `account_guard_state` 表（单行），`calc_trading_advice` 读取后叠加到总仓位档位。
2. 机会评级：`action_desk.py` 输出 `opportunity: S/A/B/无`（S=冰点/大跌日抄底档，A=修复主升，B=高位震荡，无=退潮/极热），与周期调度共用 cycle 判定。

**验收**：构造连续3笔亏损的模拟流水，熔断触发且次日推荐无 daban 票；行动台显示机会评级。
**回滚**：熔断阈值设为不可能值即关闭。

## 6. 第3批：打板分层（数据先行，预计12月）

### P1-2 打板分层：最优组合落地 + 可成交性分级（预估 L，3天+数据等待）

**目标**：回答「早盘主线板的 T+1 是不是显著优于尾盘跟风板」，把研究得出的最优组合（首/二板 + 20日≤40% + 量比≤3）显式落地为模式，并把「竞价可买到比例」纳入模式分级。**注意（勘误①）：buy_rules 对连板数没有限制，不存在「放宽连板数」这件事——要补的是最优组合落地与分层数据。**

**改动点**：
1. **数据回补**（10-19 即可启动，跑历史不占用盘中）：
   - `_em_zt_pool_get(date_str)`（`review.py:302`）**支持历史日期**——写 `server/scripts/backfill_zt_pool.py`，从 2025-01-03 起逐交易日回补涨停池（含 fund/lbc/hybk/fbt 首次封板时间），落新表 `zt_pool_daily`（每天约 40～120 行，一年约 2 万行）；
   - 限流纪律：每请求间隔 0.5s，单日失败重试2次，断点续传（沿用 `sync_market_cap.py` 的模式）；
   - 同时从今日起，`sentiment.py _sync_collect` 每晚把当日涨停池落 `zt_pool_daily`（保证未来数据不断）。
2. **分层分析**：`server/scripts/limitup_stratify.py`——按「封板时间（≤10:00 / 10:00～14:00 / >14:00）× 题材地位（主线内/分支/跟风，用 hybk 与当日 leadSectors 对齐）× 连板数（首板/二板/三板+）× 竞价≤+2% 可买到比例」切格，算各格 T+1 收益（本地K线库）。
   - 已知基线（1094口径）：首板 57.9%/+1.68%（可买61.2%）、二板 61.7%/+2.61%（49.3%）、三板 68.7%/+3.81%（39.4%）、四板+ 66.4%/+3.23%（39.9%）——**板越高期望越高、也越买不到**，分层必须同时输出两个维度。
3. **结论落地**（仅当数据支持）：
   - 最优组合落地为显式「打板模式」参数（`BUY_RULES_OPTIMAL_COMBO` 配置：首/二板 + 20日≤40% + 量比≤3），classify 的 verdict 增加 combo 达标标记；
   - 若「早盘主线板」显著优于「尾盘跟风板」→ `buy_rules.classify` 的打板条目按封板时间分层给 verdict；`recommend.py` 打板过滤增加时间维度；尾盘弱封板、非主线跟风板排除；
   - `recommend.py` 输出「可买到概率」徽章（按连板数查表），高连板票提示需竞价早动手；
   - 若分层不显著 → **维持现状**，把分析结论写进更新后的 `docs/短线买法-2026-10.md`（1094口径版）附录，避免凭信仰改代码。

**验收**：`zt_pool_daily` 覆盖 2025-01 至今且完整率 ≥95%；分层表每格样本量 ≥100 才下结论。
**风险**：东财历史池接口可能对更早日期缺字段——先跑 10 个交易日验证字段完整性再全量回补。
