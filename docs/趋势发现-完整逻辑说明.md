## 2. 趋势股入选条件（中短线波段评分，V4.0）

> **关注周期**：未来 ～1 个月
> **评分结构**：基础分(100分) - 扣分项(含互斥衰减) + 加分项 + 板块动量修正 = 最终总分
> **强制排除项**：直接剔除，不进入评分

---

### 2.1 基础分（100分，共4项）

| # | 维度 | 分值 | 得分档 | 判定标准 |
|---|------|------|--------|----------|
| 1 | 短期均线趋势 | 30 | 趋势20 + 乖离0～-10 | 趋势方向：近10日全在MA20上+MA20连升=20；近7日仅1日跌破次日收回=15；现价站稳=8。乖离惩罚：偏离MA20≥15%扣10分；≥10%扣6分；≥5%扣3分（追高风险惩罚） |
| 2 | 短期资金异动 | 30 | 30 / 25 / 20 / 12 / 0 | **连板高度分层**（业界龙头战法核心）：5连板+=市场总龙头30；3-4连板=板块龙头25；2连板=替补龙20；首板=12；无涨停且阳线<3根=0（连板分与连阳分取高，无连板时fallback到涨停次数评分） |
| 3 | 量能配合 | 20 | 量比10+趋势斜率5+稳定性5 | 量比(20日/60日)：≥1.5→10分；趋势斜率(归一化)：≥0.3→5分；稳定性(CV)：≤0.3→5分。三个子维度分别评估量的大小、方向、健康度 |
| 4 | 风险回撤 | 20 | 20 / 15 / 10 / 5 / 0 | **当前距近10日高点回撤**<8%= 20分；8%～12% =15分；12%～15% =10分；15%～20%= 5分；≥20%= 0分。已创新高则回撤≈0满分 |

---

### 2.2 扣分项（12项，分3组互斥衰减，同组只取扣分最大值）

> **2026-06-17 新增**：扣分项分组互斥，防止同类风险重复惩罚。均线趋势组(MA20/MA60_MA120/中高位)、量价异常组(放量滞涨/量价背离/缩量阴跌)、极端事件组(跌停/天地板/单日大跌)各取最大值。

| 扣分 | 条件 | 说明 |
|------|------|------|
| -10（**可豁免**） | 现价250日分位≥80% **且近20日涨幅<20%** | 年度高位但非新高突破扣10分；新高突破（近20日涨≥20%）豁免 |
| -8 | MA60与MA120同步向下 | 中长期双空头 |
| -5 | 60%≤分位<80%或MA60↓/MA120↑ | 中期空头或高位震荡 |
| -6 | 近5日跌破MA20且3日未收回 | 短期破位 |
| -15（**可豁免**） | 近20日单日跌停，**豁免**：近3日≥2涨停（连板修复） | 洗盘/利空出尽后的强势修复可豁免 |
| -10 | 持续缩量阴跌（近5日量<60日均量50%） | 流动性枯竭 |
| -10 | 单日成交量创20日新高，涨幅-1%～1%（微涨/微跌+巨量） | 放量滞涨，排除大跌放量和涨停放量 |
| -6 | 近5日股价微涨但20日均量放大超30% | 量价顶背离 |
| -8 | 近20日振幅≥15%且收跌 | 天地板/炸板 |
| -8 | 单日大跌超-7%且次日未修复 | 破位下杀 |
| -10（**位置感知**） | 近20日振幅<5%：高位扣满10分、中位扣5分、**低位不扣反加3分** | 低位窄幅横盘是蓄力形态 |
| -5 | 非主板（创业板/科创板） | 波动大，降低权重 |

---

### 2.3 加分项（6项+横盘蓄力，缩放后贡献 0～5 分）

> 加分项原始值合计最大 23 分（稳步上行与加速拉升互斥，取稳步上行 +3 作为代表），但不会直接叠加到基础分上，而是按 `(bonus_score / 23) * 5` 缩放到 0～5 分后附加，最终总分封顶 100。这样既保留"加分=质地更好"的区分度，又避免强势票全部拿到 100 分无法排序。

| 加分（原始值） | 缩放后上限 | 条件 |
|------|------|------|
| +6 | ～1.3 | MA20>MA60>MA120标准多头排列，且现价分位<60% |
| +4 | ～0.9 | 近3日倍量突破（日量≥20日均量×2，涨幅≥5%） |
| +4 | ～0.9 | 近5日连续阳线且每日涨幅≥1% |
| +3 | ～0.7 | 口袋支点：倍量(≥1.5倍)+收于日高80%以上+收盘突破前日高点 |
| +3 / +1（互斥） | ～0.7 / ～0.2 | **稳步上行 +3**：近20日涨幅5%-15% + 阳线占比≥60% + 最大单日涨幅<5%；**加速拉升 +1**：近5日涨幅≥15% + 量比≥2（警示透支风险，低加分）。两者互斥，加速拉升时给低分以示风险 |
| +3 | ～0.7 | 低位横盘蓄力：振幅<5%+250日分位<30%（加分替代扣分） |

### 2.4 日内动量加成（v5.4 新增）

> 日内强势股（涨幅≥5%）在三修正系数叠加后获得额外评分加成，直接加到 `total_score`（封顶 100），避免涨停/大涨股因反弹过滤阈值未达标而评分偏低被误杀。

| 日内涨幅 | 加成 | 说明 |
|----------|------|------|
| ≥ 9% | **+10 分** | 涨停/近涨停，强动量确认 |
| ≥ 7% | **+8 分** | 大涨，显著动量 |
| ≥ 5% | **+5 分** | 温和动量 |
| < 5% | 0 | 不加成 |

### 2.6 门槛判断

| 条件 | 值 | 说明 |
|------|----|------|
| **中期下跌过滤 ①** | MA20下方 **且** 60日累计跌幅 > 15% | **2026-06-18 新增**：避免"短线反弹但中长期下跌"的票误判为趋势向上，直接 `isUp=False` |
| **中期下跌过滤 ②（v5.4）** | MA 偏空（双空头/死亡交叉/现价<MA120 三选一）**且** 距全量历史高点回撤 > **30%**；**日内涨幅 ≥ 7% 豁免**（涨停/大涨股不适用反弹过滤） | **2026-07-09 v5.4 放宽**：回撤阈值 20%→30%（避免深跌后反弹被误杀）；新增涨停/大涨股豁免；是 `is_up_trend()` 接收 `intraday_change_pct` 参数驱动 |
| **isUp 门槛** | ≥ 35分 | 认定为"趋势向上"，进入备选池 |
| **趋势池门槛** | ≥ 65分 | 从isUp中筛选，最终进入趋势发现列表 |
| **自动加入股票池门槛** | ≥ 80分 | 满足该分数的趋势股会自动写入 `user_scan_pool`，方便后续重点跟踪（阈值配置见 `TREND_AUTO_ADD_POOL_THRESHOLD`） |
| **RSI 极度超买** | RSI ≥ 95 | 强制排除，不进入评分（超买严重，追高风险极大） |
| **RSI 严重超买** | RSI ≥ 88 | 扣 8 分（超买区，追高风险惩罚） |
| **连板透支** | 连板 ≥ 5 | 扣 10 分（连板过多，透支风险极大） |

### 2.7 自动加入股票池（2026-06-25 新增）

趋势扫描完成后，系统会额外执行一次高分自动入池：

1. 取出本次扫描所有得分 ≥ `TREND_AUTO_ADD_POOL_THRESHOLD`（默认 **80 分**）的趋势股
2. 过滤掉已经在 `user_scan_pool` 中的股票
3. 批量插入 `user_scan_pool`，并记录日志
4. 前端趋势发现页顶部会显示本次自动加入的股票数量

> 阈值设为 0 或负数时，自动加池功能关闭；修改 `server/app/config.py` 后热加载即可生效，无需重启。

### 2.8 板块动量修正（已实现）

> **2026-06-30 升级**：基于个股概念标签（`stock_concept_tags`）的同题材平均涨幅做板块动量环境修正，个股评分最终乘以 `(1 + sectorFactor)`，热门板块加成、冷门板块折价。
>
> **数据来源**：扫描时复用 `load_stock_concept_tags()` 获取每只股票的概念标签，再批量获取扫描池内所有股票的当日涨幅，按概念标签聚合求平均，作为该板块当日动量代理指标。每只股票的 `sectorChange` = 其所属多个概念标签平均涨幅的算术平均。
>
> **修正系数分档**（`TREND_SECTOR_FACTOR_TIERS` / `TREND_SECTOR_FACTOR_COLD`）：
>
> | 板块平均涨幅 | sectorFactor | 说明 |
> |--------------|--------------|------|
> | ≥ 3% | +0.05 | 热门板块加成 5% |
> | ≥ 1% | +0.03 | 偏热板块加成 3% |
> | -1% ～ 1% | 0.0 | 中性板块不修正 |
> | ≤ -1% | -0.03 | 偏冷板块折价 3% |
> | ≤ -3% | -0.05 | 冷门板块折价 5% |
>
> **降级策略**：板块动量预计算失败时（如概念标签缺失、行情获取异常），`sector_change=None` → `sectorFactor=0.0` 不修正，不影响主评分流程。
>
> **乘性修正系数族（2026-06-30）**：板块动量、筹码结构、量价形态三者为同族乘性修正，最终总分公式为 `total = raw_score × (1 + min(TREND_TOTAL_FACTOR_CAP, sectorFactor + chipFactor + patternFactor))`，三系数叠加总和封顶 `0.15`（防溢出），再 `min(100, …)`。各系数独立计算、互不干扰：
> - `sectorFactor`（，本节）：±5%，板块环境修正
> - `chipFactor`：±8%，筹码结构代理指标（MA成本+换手+主力净流入+量能CV）
> - `patternFactor`：±4%，量价6形态互斥识别
>
> 另有 **动态阈值**（非乘性修正，而是按 `market_regime × pattern` 三级优先覆盖 D1/D3/D4 扣分阈值），与上述乘性修正并存：牛市放宽乖离、收紧破位；熊市收紧乖离/回撤；形态特化加重滞涨/背离/横盘扣分。

### 2.9 评分流程示例

| 步骤 | 操作 | 得分变化 |
|------|------|----------|
| 1 | 计算基础分（满分 100）：D1=18(趋势20-乖离扣2),D2=20,D3=14(量比8+斜率3+稳定3),D4=20 | **72** |
| 2 | 扣分（互斥衰减后）：中高位-5, 跌破MA20-6（均线组已取最大） | 72 − 11 = **61** |
| 3 | 加分缩放：触发多头排列(5)+倍量突破(4)=9 → 缩放 (9/18)*5 = 2.5 | 61 + 2.5 = **63.5** |
| 4 | 三修正系数叠加（封顶 0.15）：板块+0.05 + 筹码+0.03 + 形态+0.04 = 0.12 | totalFactor = min(0.15, 0.12) = **0.12** |
| 5 | 乘性修正：raw × (1 + totalFactor) | 63.5 × 1.12 = **71.1** |
| 6 | 最终得分 71.1 ≥ 35 → **isUp = true**；≥ 65 → 进入趋势池 | — |


### 2.10 早期信号层（第5维度，2026-08-17 新增）

> 在 V4.0 四维度评分系统上叠加"早期信号加成层"，识别"趋势形成前"的转折信号，降低整体滞后性（均线系统内在滞后 2-5 天）。参考 Mark Minervini SEPA 体系 + 经典技术分析形态。
>
> **实现**：`services/early_signals.py`（5 个纯函数检测器 + 1 个聚合函数），仅依赖 OHLCV 序列，无 IO/无状态。在 `is_up_trend()` 评分流程末尾调用，加成直接叠加到 `total_score`（封顶 100）。

**性能 gating**（避免给所有票都跑 5 个检测器）：
- 全局开关 `TREND_EARLY_SIGNAL_ENABLED`（默认开启）
- 仅 `base_score ∈ [40, 92]` 时运行（边界股才有早期信号价值；太弱无意义，太强已确认）
- `RSI ≥ 88` 时不运行（避免给超买股加分）
- 位置分位 > 70 时，NR7/VCP 两个检测器跳过（高位无早期信号价值）
- 单检测器异常不影响其他（容错 try/except）

| 检测器 | 信号名称 | 命中条件 | 加分 | 说明 |
|--------|----------|----------|------|------|
| NR7 / Inside Bar | `nr7_inside_bar` | 当前7日区间为近30日最小 + Inside Bar或缩量确认 | +3 | 波动率收缩到极致，变盘在即 |
| VCP 波动率收缩 | `vcp` | 近30日2-3次枢轴间振幅严格递减 + 量能递减 | +3 | Minervini SEPA 核心买入形态：收缩到极致后突破概率高 |
| RSI 底背离 | `rsi_bottom_div` | 价格创新低但RSI抬高 + RSI < 50 | +3 | 下跌动能衰竭，底部反转前兆 |
| 底部首板 | `bottom_first_limit` | 今日涨停 + 近60日无其他涨停 + 位置分位 < 50% | +3 | 低位首板，趋势启动信号 |
| 缩量后首放 | `consolidation_break` | 前7日区间收敛+缩量，当日倍量阳线突破 | +3 | 与 pattern.py 的 volume_breakout 互斥去重 |

**封顶**：`bonus = min(命中数 × PER_HIT_SCORE, MAX_BONUS)`（每命中 +3，最多 +10 分）

**前端展示**：趋势发现页展开卡片中显示"早期信号"标签（橙色系，呼应"早期/未确认"语义），鼠标悬停显示详细描述。

**配置项**（`config.py`）：`TREND_EARLY_SIGNAL_ENABLED` / `TREND_EARLY_SIGNAL_PER_HIT_SCORE=3` / `TREND_EARLY_SIGNAL_MAX_BONUS=10` / `TREND_EARLY_SIGNAL_BASE_SCORE_MIN=40` / `TREND_EARLY_SIGNAL_BASE_SCORE_MAX=92` / `TREND_EARLY_SIGNAL_POSITION_GATE=70` + 各检测器专属参数。

## 4. 趋势股移除逻辑

### 4.1 自动移除（每次扫描时）

趋势扫描是**全量替换**机制：每次 `/api/scan-trend-stocks` 执行时：
1. 先 `DELETE` 数据库中当天（同 `scan_date`）的所有旧记录
2. 重新全量扫描所有股票
3. 将符合条件的 `INSERT` 入数据库

→ **不满足条件的自动消失，新符合条件的自动出现**

### 4.2 5日/10日线跌破移除（统一入口 + 盘中实时校准）

| 机制 | 触发时机 | 说明 |
|------|----------|------|
| **统一硬过滤** | 每次趋势扫描 | `is_up_trend()` 函数第一关就拒绝，价格源为**实时价**（盘中）或**收盘价**（盘后） |
| **实时价校准** | 09:30/11:30/13:00/15:00 定时扫描 | 扫描时优先取 `priceRaw` 实时价重算 MA5/MA10，盘中跌破立即移除 |
| **定时检查** | 每天 15:05 | `check_below_ma10()` 扫描**用户股票池**（非趋势池），跌破且未收回的直接删除（兜底） |

> **设计权衡说明**：系统采用盘中实时价判断是否跌破均线，目的是尽快识别转弱信号，避免用户看到已破位的股票。
> **可能副作用**：股票盘中短暂刺破均线但收盘收复，会被临时移出趋势池，需等待下一次全量扫描（通常次日）才会重新加入。
> **替代方案**：如需更稳健的判断，可在 `config.py` 中将 `USE_INTRADAY_BREAK_CHECK` 设为 `false`，改为仅用收盘价判断（或改为"连续两个收盘价跌破"再移除）。

**优化点**：
1. **数据滞后修复**：原逻辑只用 K 线收盘价判断，无法发现盘中跌破；现增加实时价校准
2. **检查入口统一**：5日/10日线检查从两处（`is_up_trend` + `check_below_ma10`）合并为一处
3. **冗余去除**：删除 `MA60>MA120` 重复评分项，分数重新分配给其他项

## 5. 趋势评分计算流程

```
扫描池中每只股票
  ├─ 获取K线 → is_up_trend(kline, realtime_price)
  │   ├─ K线天数 < 60?  →  拒绝 ❌
  │   ├─ 强制排除（ST/利空/连续跌停/小市值/行业关键词）  →  拒绝 ❌
  │   ├─ 4维度基础分（满分100）：
  │   │   D1 短期均线趋势 30分（趋势方向20 + 乖离惩罚0～-10）
  │   │   D2 短期资金异动 30分（连板高度分层/连阳数取高）
  │   │   D3 量能配合    20分（量比10 + 趋势斜率5 + 稳定性5）
  │   │   D4 风险回撤    20分（距近10日高点回撤，5档）
  │   ├─ 动态阈值：market_regime(bull/bear/range) × pattern 三级优先覆盖
  │   │   D1乖离/D3放量滞涨/D4回撤/破位/背离/横盘 扣分阈值
  │   ├─ 12项扣分（分3组互斥衰减，同组取最大值，阈值由 动态调整）
  │   ├─ 5项加分（缩放到0～5分附加，总分封顶100）
  │   ├─ 乘性修正系数族（封顶 0.15）：
  │   │   total = raw × (1 + min(0.15, sectorFactor + chipFactor + patternFactor))
  │   │   • sectorFactor  板块动量 ±5%
  │   │   • chipFactor    筹码结构（MA成本+换手+主力净流入+量能CV）±8%
  │   │   • patternFactor  量价6形态 ±4%
  │   ├─ 中期下跌过滤①：MA20下方 + 60日跌幅>15%  →  isUp=false
  │   ├─ 中期下跌过滤②：MA偏空 + 距历史高点回撤>30%（日内涨幅≥7%豁免）  →  isUp=false
  │   ├─ 日内动量加成：涨幅≥9%+10 / ≥7%+8 / ≥5%+5 → 直接加到 total_score
  │   └─ 总分 ≥ 35?  →  isUp=true
  ├─ 获取股票名称 → 为空? → 跳过
  ├─ 检查退市风险 → 有风险? → 跳过
  ├─ 非沪深主板 → 扣5分（不跳过）
  ├─ 总分 ≥ 60?   → 进入趋势池
  ├─ 总分 ≥ 80?   → 自动加入用户股票池
  └─ 按分数降序排列 → 存入数据库
```

## 6. 前端加载策略

| 场景 | 行为 |
|------|------|
| 首次打开趋势发现 | 先展示缓存数据（秒开），同时检测 `scanDate` 是否过期 |
| 数据已过期 | 后台自动触发 `/api/scan-trend-stocks` 异步扫描 |
| 数据是今天的 | 直接展示，每隔30秒（盘中）/ 5分钟（盘后）自动刷新 |
| 缓存数据为空 | 显示"正在扫描"，然后触发完整扫描 |

**盘中 / 盘后定义**：

| 状态 | 时间范围 |
|------|----------|
| **盘中** | 交易日的 **09:30-11:30** 和 **13:00-15:00** |
| **盘后** | 交易日 **15:00 之后**，以及**所有非交易日**（周末、节假日） |

**节假日处理**：非交易日不触发自动刷新；前端检测到非交易日时，直接使用缓存数据并显示"休市"。

> **非交易日一律跳过盘中与当日任务**（`services/data/trading_calendar.is_trading_day`）——
> 否则周六 15:10 那份"空收评"会把周五的真实收评顶掉。唯一例外是**周六 08:30 的本地因子体检**：
> 只读本地库、不联网、不写当日业务数据，选周末跑是为了不占盘中调度线程。盘后慢变数据另有一套**贴着源头披露周期**的节奏
> （2026-10-19 降频专项，`app/config.py` 的 `SLOW_DATA_*`，重启生效）：股东户数**周一/周四**、基本面**周一**，
> 财报季（1/3/4/7/8/10 月）自动恢复每日含周末——那几个月周末公告最密，新披露不能等一周；
> 估值分位**仅交易日**（周末没有新收盘价，拉回来还是同一份）。这三位非刷新日只打一行日志、零请求，
> 把节奏开关置空（`SLOW_DATA_*_WEEKDAYS = []` / `SLOW_DATA_VALUATION_TRADING_ONLY = False`）即完全退回每日含周末的老行为。
> 只有聪明钱（17:30 刷新至最近已收盘交易日）保持 7 天无休，市值周刷新与 02:10 矩阵重跑同样照跑。
>
> **调度稳健性**：`run_scheduler()` 主循环包 try-except，单个 job 抛错不会带崩整条线程；
> 日志带时间戳与异常堆栈前 400～500 字符。schedule 库的 `.day.at()` 在 60 秒粒度下可能漏触发，
> 因此主循环每 30 秒额外自检一次（例如 15:10 之后今日收评仍缺失就自动补生成，最多 3 次）。
> 盘后数据新鲜度另有 `_alert_kline_stale()` 自检，按**范围内覆盖度**告警（文案是 `X/2462` 那种分母）。
>
> 时刻都能改，但改的是**默认值**：`app/config.py` 里的 `SCHEDULE_*_TIME` / `KLINE_HISTORY_SYNC_TIMES`
> 等属于重启才生效的一类；界面「口径与开关」里能热改的是已经做成"用的时候现读"的那几项。
