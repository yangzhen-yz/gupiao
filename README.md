# A股短线交易台（行情 · 选股 · 推荐 · 持仓 · 复盘 · 推送）

最初它是个"A股实时行情查询"，现在是一整套围绕短线决策的工作台：盘中出信号、盘后做复盘、
选票口径可以在界面上改、每天的决策现场会落库供以后回放。
后端 FastAPI + SQLite（单机自托管，无外部数据库），前端 Vue 3 + Vite，企业微信推送。

## 一页速览

| 分组 | 页面 | 回答的问题 |
|------|------|------------|
| 首页 | **行动台** (`tab-desk`) | 现在这个时刻该做什么：买入区/持仓处理/环境否决，情绪周期直接参与硬拦 |
| 盘面 | 实时行情 · 股票筛选 · 趋势发现 · 资金流向 | 价、量、形态、板块资金在说什么 |
| 决策 | 智能推荐 · 持仓管理 · 模拟交易 | 推哪 3 只（含买卖点与买入时机）、手里的怎么处理、不改真钱先验证想法 |
| 复盘 | 每日收评 · 自动优化 · **口径与开关** | 昨天推得对不对、权重该怎么调、六条选股口径与各项阈值现场改 |

**选股口径（所有入口共用，2026-10-16 收口成两层）**

- **数据范围 2462** = 沪深主板（600/601/603/605/000/001/002/003）+ 非 ST/\*ST/退市整理 + 总市值 ≥ 35 亿
  —— 它决定"日K同步清单"和一切覆盖率的分母。
- **选票范围 1094** = 在数据范围之上再叠 近 20 交易日日均成交额 > 0.8 亿、日均换手率 > 1.5%、股价 > 3 元
  —— 它决定海选百分位排名、智能推荐入口、趋势扫描、盘中扫描与推送。
- 唯一出处 [`server/services/data/universe.py`](server/services/data/universe.py) 与
  [`server/services/data/liquidity.py`](server/services/data/liquidity.py)；六条各有独立开关，
  关掉任何一条都会在页面上实时报"放回多少只"。**别让流动性条件去管同步清单**——
  缩量票今天进清单明天出清单，历史序列就会挖洞，MA60 / 60 日高点 / RPS 全被洞污染。

## 快速开始

```bash
cd server
start.bat            # Windows 双击即可：构建前端 → 装依赖 → 起 FastAPI（端口 3003）
```

`start.bat` → `start.py` 的顺序是：① 构建前端（首次 `pnpm install`，之后增量 `pnpm run build`）
② 检查 Python（`python3` / `python`）③ 装/更新 `requirements.txt`（清华源失败自动回退默认源）
④ 启动 `run.py`（uvicorn，`reload=True` 监视 `app/`、`services/`、`db/`，改这些目录下的 .py 会自动重载）。

访问 <http://localhost:3003> 使用应用；API 文档在 <http://localhost:3003/docs>。

### 首次使用：注册账号

系统是多用户（持仓、股票池、推送绑定都按账号隔离），**首次打开会进登录页**：

1. 在登录页切到「注册」，填用户名 + 密码（≥6 位）
2. **第一个注册的账号会天然继承库里已有的历史持仓**——存量持仓迁移时被挂在 `user_id=1`，
   而首个注册者的自增 id 正好是 1（顺序约束写在 `services/support/auth.py`：先迁库后注册会让
   存量持仓变成无主孤儿）。之后注册的账号从零开始，彼此看不到对方的持仓
3. 登录页下方会列出已有账号，点一下即自动填用户名
4. 「口径与开关」子页里能改配置的是**最早注册的那个账号**（`users` 表没有角色列，
   只能这样定管理员；想指定别人就改 `SETTINGS_WRITE_USER_IDS`）

不想开放自助注册 → `AUTH_ALLOW_REGISTER = False`；想整体关掉登录（回到单用户）→ `AUTH_ENABLED = False`。

## 趋势发现 - 完整逻辑说明（核心）

### 1. 扫描数据源

| 优先级 | 数据源 | 说明 |
|--------|--------|------|
| 主要 | 东方财富热搜榜（`hot_search_daily_snapshot` 表） | 3 类榜单合并：真实人气榜前100 + 涨幅榜前100 + 成交额榜前400，去重后约 470~500 只沪深主板 |
| 备用 | `HOT_STOCK_POOL` + `stock_basic_info` | 热搜榜为空时的本地股票池 |

### 2. 趋势股入选条件（中短线波段评分，V4.0）

> **关注周期**：未来 ~1 个月
> **评分结构**：基础分(100分) - 扣分项(含互斥衰减) + 加分项 + 板块动量修正 = 最终总分
> **强制排除项**：直接剔除，不进入评分

---

#### 2.1 基础分（100分，共4项）

| # | 维度 | 分值 | 得分档 | 判定标准 |
|---|------|------|--------|----------|
| 1 | 短期均线趋势 | 30 | 趋势20 + 乖离0~-10 | 趋势方向：近10日全在MA20上+MA20连升=20；近7日仅1日跌破次日收回=15；现价站稳=8。乖离惩罚：偏离MA20≥15%扣10分；≥10%扣6分；≥5%扣3分（追高风险惩罚） |
| 2 | 短期资金异动 | 30 | 30 / 25 / 20 / 12 / 0 | **连板高度分层**（业界龙头战法核心）：5连板+=市场总龙头30；3-4连板=板块龙头25；2连板=替补龙20；首板=12；无涨停且阳线<3根=0（连板分与连阳分取高，无连板时fallback到涨停次数评分） |
| 3 | 量能配合 | 20 | 量比10+趋势斜率5+稳定性5 | 量比(20日/60日)：≥1.5→10分；趋势斜率(归一化)：≥0.3→5分；稳定性(CV)：≤0.3→5分。三个子维度分别评估量的大小、方向、健康度 |
| 4 | 风险回撤 | 20 | 20 / 15 / 10 / 5 / 0 | **当前距近10日高点回撤**<8%= 20分；8%~12% =15分；12%~15% =10分；15%~20%= 5分；≥20%= 0分。已创新高则回撤≈0满分 |

---

#### 2.2 扣分项（12项，分3组互斥衰减，同组只取扣分最大值）

> **2026-06-17 新增**：扣分项分组互斥，防止同类风险重复惩罚。均线趋势组(MA20/MA60_MA120/中高位)、量价异常组(放量滞涨/量价背离/缩量阴跌)、极端事件组(跌停/天地板/单日大跌)各取最大值。

| 扣分 | 条件 | 说明 |
|------|------|------|
| -10（**可豁免**） | 现价250日分位≥80% **且近20日涨幅<20%** | 年度高位但非新高突破扣10分；新高突破（近20日涨≥20%）豁免 |
| -8 | MA60与MA120同步向下 | 中长期双空头 |
| -5 | 60%≤分位<80%或MA60↓/MA120↑ | 中期空头或高位震荡 |
| -6 | 近5日跌破MA20且3日未收回 | 短期破位 |
| -15（**可豁免**） | 近20日单日跌停，**豁免**：近3日≥2涨停（连板修复） | 洗盘/利空出尽后的强势修复可豁免 |
| -10 | 持续缩量阴跌（近5日量<60日均量50%） | 流动性枯竭 |
| -10 | 单日成交量创20日新高，涨幅-1%~1%（微涨/微跌+巨量） | 放量滞涨，排除大跌放量和涨停放量 |
| -6 | 近5日股价微涨但20日均量放大超30% | 量价顶背离 |
| -8 | 近20日振幅≥15%且收跌 | 天地板/炸板 |
| -8 | 单日大跌超-7%且次日未修复 | 破位下杀 |
| -10（**位置感知**） | 近20日振幅<5%：高位扣满10分、中位扣5分、**低位不扣反加3分** | 低位窄幅横盘是蓄力形态 |
| -5 | 非主板（创业板/科创板） | 波动大，降低权重 |

---

#### 2.3 加分项（6项+横盘蓄力，缩放后贡献 0~5 分）

> 加分项原始值合计最大 23 分（稳步上行与加速拉升互斥，取稳步上行 +3 作为代表），但不会直接叠加到基础分上，而是按 `(bonus_score / 23) * 5` 缩放到 0~5 分后附加，最终总分封顶 100。这样既保留"加分=质地更好"的区分度，又避免强势票全部拿到 100 分无法排序。

| 加分（原始值） | 缩放后上限 | 条件 |
|------|------|------|
| +6 | ~1.3 | MA20>MA60>MA120标准多头排列，且现价分位<60% |
| +4 | ~0.9 | 近3日倍量突破（日量≥20日均量×2，涨幅≥5%） |
| +4 | ~0.9 | 近5日连续阳线且每日涨幅≥1% |
| +3 | ~0.7 | 口袋支点：倍量(≥1.5倍)+收于日高80%以上+收盘突破前日高点 |
| +3 / +1（互斥） | ~0.7 / ~0.2 | **稳步上行 +3**：近20日涨幅5%-15% + 阳线占比≥60% + 最大单日涨幅<5%；**加速拉升 +1**：近5日涨幅≥15% + 量比≥2（警示透支风险，低加分）。两者互斥，加速拉升时给低分以示风险 |
| +3 | ~0.7 | 低位横盘蓄力：振幅<5%+250日分位<30%（加分替代扣分） |

#### 2.4 日内动量加成（v5.4 新增）

> 日内强势股（涨幅≥5%）在三修正系数叠加后获得额外评分加成，直接加到 `total_score`（封顶 100），避免涨停/大涨股因反弹过滤阈值未达标而评分偏低被误杀。

| 日内涨幅 | 加成 | 说明 |
|----------|------|------|
| ≥ 9% | **+10 分** | 涨停/近涨停，强动量确认 |
| ≥ 7% | **+8 分** | 大涨，显著动量 |
| ≥ 5% | **+5 分** | 温和动量 |
| < 5% | 0 | 不加成 |

#### 2.6 门槛判断

| 条件 | 值 | 说明 |
|------|----|------|
| **中期下跌过滤 ①** | MA20下方 **且** 60日累计跌幅 > 15% | **2026-06-18 新增**：避免"短线反弹但中长期下跌"的票误判为趋势向上，直接 `isUp=False` |
| **中期下跌过滤 ②（v5.4）** | MA 偏空（双空头/死亡交叉/现价<MA120 三选一）**且** 距全量历史高点回撤 > **30%**；**日内涨幅 ≥ 7% 豁免**（涨停/大涨股不适用反弹过滤） | **2026-07-09 v5.4 放宽**：回撤阈值 20%→30%（避免深跌后反弹被误杀）；新增涨停/大涨股豁免；是 `is_up_trend()` 接收 `intraday_change_pct` 参数驱动 |
| **isUp 门槛** | ≥ 35分 | 认定为"趋势向上"，进入备选池 |
| **趋势池门槛** | ≥ 65分 | 从isUp中筛选，最终进入趋势发现列表 |
| **自动加入股票池门槛** | ≥ 80分 | 满足该分数的趋势股会自动写入 `user_scan_pool`，方便后续重点跟踪（阈值配置见 `TREND_AUTO_ADD_POOL_THRESHOLD`） |
| **RSI 极度超买** | RSI ≥ 95 | 强制排除，不进入评分（超买严重，追高风险极大） |
| **RSI 严重超买** | RSI ≥ 88 | 扣 8 分（超买区，追高风险惩罚） |
| **连板透支** | 连板 ≥ 5 | 扣 10 分（连板过多，透支风险极大） |

#### 2.7 自动加入股票池（2026-06-25 新增）

趋势扫描完成后，系统会额外执行一次高分自动入池：

1. 取出本次扫描所有得分 ≥ `TREND_AUTO_ADD_POOL_THRESHOLD`（默认 **80 分**）的趋势股
2. 过滤掉已经在 `user_scan_pool` 中的股票
3. 批量插入 `user_scan_pool`，并记录日志
4. 前端趋势发现页顶部会显示本次自动加入的股票数量

> 阈值设为 0 或负数时，自动加池功能关闭；修改 `server/app/config.py` 后热加载即可生效，无需重启。

#### 2.8 板块动量修正（已实现）

> **2026-06-30 升级**：基于个股概念标签（`stock_concept_tags`）的同题材平均涨幅做板块动量环境修正，个股评分最终乘以 `(1 + sectorFactor)`，热门板块加成、冷门板块折价。
>
> **数据来源**：扫描时复用 `load_stock_concept_tags()` 获取每只股票的概念标签，再批量获取扫描池内所有股票的当日涨幅，按概念标签聚合求平均，作为该板块当日动量代理指标。每只股票的 `sectorChange` = 其所属多个概念标签平均涨幅的算术平均。
>
> **修正系数分档**（`TREND_SECTOR_FACTOR_TIERS` / `TREND_SECTOR_FACTOR_COLD`）：
>
> | 板块平均涨幅 | sectorFactor | 说明 |
> |--------------|--------------|------|
> | ≥ 3% | +0.05 | 热门板块加成 5% |
> | ≥ 1% | +0.03 | 偏热板块加成 3% |
> | -1% ~ 1% | 0.0 | 中性板块不修正 |
> | ≤ -1% | -0.03 | 偏冷板块折价 3% |
> | ≤ -3% | -0.05 | 冷门板块折价 5% |
>
> **降级策略**：板块动量预计算失败时（如概念标签缺失、行情获取异常），`sector_change=None` → `sectorFactor=0.0` 不修正，不影响主评分流程。
>
> **乘性修正系数族（2026-06-30）**：板块动量、筹码结构、量价形态三者为同族乘性修正，最终总分公式为 `total = raw_score × (1 + min(TREND_TOTAL_FACTOR_CAP, sectorFactor + chipFactor + patternFactor))`，三系数叠加总和封顶 `0.15`（防溢出），再 `min(100, …)`。各系数独立计算、互不干扰：
> - `sectorFactor`（，本节）：±5%，板块环境修正
> - `chipFactor`：±8%，筹码结构代理指标（MA成本+换手+主力净流入+量能CV）
> - `patternFactor`：±4%，量价6形态互斥识别
>
> 另有 **动态阈值**（非乘性修正，而是按 `market_regime × pattern` 三级优先覆盖 D1/D3/D4 扣分阈值），与上述乘性修正并存：牛市放宽乖离、收紧破位；熊市收紧乖离/回撤；形态特化加重滞涨/背离/横盘扣分。

#### 2.9 评分流程示例

| 步骤 | 操作 | 得分变化 |
|------|------|----------|
| 1 | 计算基础分（满分 100）：D1=18(趋势20-乖离扣2),D2=20,D3=14(量比8+斜率3+稳定3),D4=20 | **72** |
| 2 | 扣分（互斥衰减后）：中高位-5, 跌破MA20-6（均线组已取最大） | 72 − 11 = **61** |
| 3 | 加分缩放：触发多头排列(5)+倍量突破(4)=9 → 缩放 (9/18)*5 = 2.5 | 61 + 2.5 = **63.5** |
| 4 | 三修正系数叠加（封顶 0.15）：板块+0.05 + 筹码+0.03 + 形态+0.04 = 0.12 | totalFactor = min(0.15, 0.12) = **0.12** |
| 5 | 乘性修正：raw × (1 + totalFactor) | 63.5 × 1.12 = **71.1** |
| 6 | 最终得分 71.1 ≥ 35 → **isUp = true**；≥ 65 → 进入趋势池 | — |


#### 2.10 早期信号层（第5维度，2026-08-17 新增）

> 在 V4.0 四维度评分系统上叠加"早期信号加成层"，识别"趋势形成前"的转折信号，降低整体滞后性（均线系统内在滞后 2-5 天）。参考 Mark Minervini SEPA 体系 + 经典技术分析形态。
>
> **实现**：`services/early_signals.py`（5 个纯函数检测器 + 1 个聚合函数），仅依赖 OHLCV 序列，无 IO/无状态。在 `is_up_trend()` 评分流程末尾调用，加成直接叠加到 `total_score`（封顶 100）。

**性能 gating**（避免给所有票都跑 5 个检测器）：
- 全局开关 `TREND_EARLY_SIGNAL_ENABLED`（默认开启）
- 仅 `base_score ∈ [40, 92]` 时运行（边界股才有早期信号价值；太弱无意义，太强已确认）
- `RSI ≥ 88` 时不运行（避免给超买股加分）
- 位置分位 > 70 时，NR7/VCP 两个检测器跳过（高位无早期信号价值）
- 单检测器异常不影响其他（容错 try/except）

| 检测器 | 信号名称 | 命中条件 | 加分 | 说明 |
|--------|----------|----------|------|------|
| NR7 / Inside Bar | `nr7_inside_bar` | 当前7日区间为近30日最小 + Inside Bar或缩量确认 | +3 | 波动率收缩到极致，变盘在即 |
| VCP 波动率收缩 | `vcp` | 近30日2-3次枢轴间振幅严格递减 + 量能递减 | +3 | Minervini SEPA 核心买入形态：收缩到极致后突破概率高 |
| RSI 底背离 | `rsi_bottom_div` | 价格创新低但RSI抬高 + RSI < 50 | +3 | 下跌动能衰竭，底部反转前兆 |
| 底部首板 | `bottom_first_limit` | 今日涨停 + 近60日无其他涨停 + 位置分位 < 50% | +3 | 低位首板，趋势启动信号 |
| 缩量后首放 | `consolidation_break` | 前7日区间收敛+缩量，当日倍量阳线突破 | +3 | 与 pattern.py 的 volume_breakout 互斥去重 |

**封顶**：`bonus = min(命中数 × PER_HIT_SCORE, MAX_BONUS)`（每命中 +3，最多 +10 分）

**前端展示**：趋势发现页展开卡片中显示"早期信号"标签（橙色系，呼应"早期/未确认"语义），鼠标悬停显示详细描述。

### 4. 趋势股移除逻辑

#### 4.1 自动移除（每次扫描时）

趋势扫描是**全量替换**机制：每次 `/api/scan-trend-stocks` 执行时：
1. 先 `DELETE` 数据库中当天（同 `scan_date`）的所有旧记录
2. 重新全量扫描所有股票
3. 将符合条件的 `INSERT` 入数据库

→ **不满足条件的自动消失，新符合条件的自动出现**

#### 4.2 5日/10日线跌破移除（统一入口 + 盘中实时校准）

| 机制 | 触发时机 | 说明 |
|------|----------|------|
| **统一硬过滤** | 每次趋势扫描 | `is_up_trend()` 函数第一关就拒绝，价格源为**实时价**（盘中）或**收盘价**（盘后） |
| **实时价校准** | 09:30/11:30/13:00/15:00 定时扫描 | 扫描时优先取 `priceRaw` 实时价重算 MA5/MA10，盘中跌破立即移除 |
| **定时检查** | 每天 15:05 | `check_below_ma10()` 扫描**用户股票池**（非趋势池），跌破且未收回的直接删除（兜底） |

> **设计权衡说明**：系统采用盘中实时价判断是否跌破均线，目的是尽快识别转弱信号，避免用户看到已破位的股票。
> **可能副作用**：股票盘中短暂刺破均线但收盘收复，会被临时移出趋势池，需等待下一次全量扫描（通常次日）才会重新加入。
> **替代方案**：如需更稳健的判断，可在 `config.py` 中将 `USE_INTRADAY_BREAK_CHECK` 设为 `false`，改为仅用收盘价判断（或改为"连续两个收盘价跌破"再移除）。

**优化点**：
1. **数据滞后修复**：原逻辑只用 K 线收盘价判断，无法发现盘中跌破；现增加实时价校准
2. **检查入口统一**：5日/10日线检查从两处（`is_up_trend` + `check_below_ma10`）合并为一处
3. **冗余去除**：删除 `MA60>MA120` 重复评分项，分数重新分配给其他项

### 5. 趋势评分计算流程

```
扫描池中每只股票
  ├─ 获取K线 → is_up_trend(kline, realtime_price)
  │   ├─ K线天数 < 60?  →  拒绝 ❌
  │   ├─ 强制排除（ST/利空/连续跌停/小市值/行业关键词）  →  拒绝 ❌
  │   ├─ 4维度基础分（满分100）：
  │   │   D1 短期均线趋势 30分（趋势方向20 + 乖离惩罚0~-10）
  │   │   D2 短期资金异动 30分（连板高度分层/连阳数取高）
  │   │   D3 量能配合    20分（量比10 + 趋势斜率5 + 稳定性5）
  │   │   D4 风险回撤    20分（距近10日高点回撤，5档）
  │   ├─ 动态阈值：market_regime(bull/bear/range) × pattern 三级优先覆盖
  │   │   D1乖离/D3放量滞涨/D4回撤/破位/背离/横盘 扣分阈值
  │   ├─ 12项扣分（分3组互斥衰减，同组取最大值，阈值由 动态调整）
  │   ├─ 5项加分（缩放到0~5分附加，总分封顶100）
  │   ├─ 乘性修正系数族（封顶 0.15）：
  │   │   total = raw × (1 + min(0.15, sectorFactor + chipFactor + patternFactor))
  │   │   • sectorFactor  板块动量 ±5%
  │   │   • chipFactor    筹码结构（MA成本+换手+主力净流入+量能CV）±8%
  │   │   • patternFactor  量价6形态 ±4%
  │   ├─ 中期下跌过滤①：MA20下方 + 60日跌幅>15%  →  isUp=false
  │   ├─ 中期下跌过滤②：MA偏空 + 距历史高点回撤>30%（日内涨幅≥7%豁免）  →  isUp=false
  │   ├─ 日内动量加成：涨幅≥9%+10 / ≥7%+8 / ≥5%+5 → 直接加到 total_score
  │   └─ 总分 ≥ 35?  →  isUp=true
  ├─ 获取股票名称 → 为空? → 跳过
  ├─ 检查退市风险 → 有风险? → 跳过
  ├─ 非沪深主板 → 扣5分（不跳过）
  ├─ 总分 ≥ 60?   → 进入趋势池
  ├─ 总分 ≥ 80?   → 自动加入用户股票池
  └─ 按分数降序排列 → 存入数据库
```

##### 9.1.1 主力扫货 & 主力控盘识别（P1-4，2026-07-07 新增）

| 识别场景 | 触发条件 | 效果 | 说明 |
|----------|----------|------|------|
| **主力扫货** | 急拉(涨≥3%) + 负委比(≤-20%) + 高外盘(≥55%) + 温和量能(量比≤2.5) + 活跃换手(≥3%) | 委比 `weibi` 强制拉到 high 档(14分)；量比 `volume_ratio` 强制拉到 high 档(14分) | 主力用大单吃掉卖盘 → 委比转为负值但实际是看涨信号，原逻辑按委比阈值只给 4 分（low），完全漏掉强看涨信号。例：东山精密 002384 急拉6.79% / 委比-26.67% / 外盘55.7% |

##### 9.1.2 涨停股次日反转风险惩罚（2026-07-08，2026-07-14 修正触发条件）

| 条件 | 是否触发反转惩罚 | 说明 |
|------|------------------|------|
| 委比 < 0 或 量比 > 8 或 外盘 < 45% | **是** | 真实弱封板/烂板/出货信号，按大盘环境处罚 |
| 委比 ≥ 0 且 量比 ≤ 8 且 外盘 ≥ 45% | **否** | 收盘委比归0属于正常数据现象，保留基础涨停分（最低18→15） |

| 大盘环境 | 惩罚 | 说明 |
|----------|------|------|
| 大盘显著下跌（< -0.5%） | **-10 分** | 涨停股次日反转风险极高（获利盘出逃） |
| 大盘微跌（-0.5% ~ 0%） | **-6 分** | 中等反转风险 |
| 大盘平盘（0% ~ +0.3%） | **-3 分** | 轻度反转风险 |

##### 9.1.3 大盘下跌门槛强化（2026-07-08，2026-07-14 调整作用范围）

> 回测数据显示大盘下跌时策略准确率偏低，因此在方向预测阈值 `bull_threshold` 上施加动态上浮，但标签阈值（≥80 强烈看涨 / ≥70 偏多看涨）保持固定，避免收盘后强势票被误标为观望：

```
大盘下跌时: penalty = min(15, int(|market_change| × 8))
bull_threshold += penalty      # 仅影响 predict_direction，不影响标签显示
```

| 大盘跌幅 | penalty | 新的方向预测门槛（bull） | 标签门槛（保持不变） |
|----------|---------|------------------------|---------------------|
| -0.5% | +4 分 | 64 分 | 60 分 |
| -1.0% | +8 分 | 68 分 | 60 分 |
| -2.0% | +15 分 | 75 分 | 60 分 |

> 这会让大盘环境不利时"推荐买入"更谨慎，但用户看到的标签仍然稳定：≥70 就是偏多看涨，不受当日大盘涨跌干扰。`total` 分数本身不受影响。

#### 9.2 选股硬性过滤规则

在生成推荐名单前，系统会执行以下硬性拦截，确保“实战可操作性”：

- **基本面安全**：自动过滤名称含 `ST` 或 `退` 的风险股。
- **成交真实性**：**分级软惩罚**（非硬过滤）。涨停股天量开板（vol>8x+outer<45%）重罚-5分，放量偏弱（vol>5x+outer<48%）轻罚-3分；非涨停股放量外盘不占优时扣-5分。正常封板不罚。
- **拥抱龙头**：**完全取消**对高涨幅股的硬过滤。允许涨停股入选，旨在发掘次日高开溢价或龙回头机会。

#### 9.3 P2/P3 优化说明（2026-06-30）

承接 P0（板块效应/连板梯队）/ P1（主力净流入/涨停质量），P2/P3 进一步补齐筹码结构、量价形态、动态阈值、行业中性化四项：

**筹码结构修正系数（`trend.py _calc_chip_factor`）**
无真实 CYQ 筹码数据，用 4 个代理指标组合刻画筹码结构，作为乘性修正系数叠加到趋势总分（钳制 ±8%）：
- 子项1 成本压力位：现价 vs MA60/MA120（双线上方 +3% / 双线下方 -5%）
- 子项2 换手率松动度：1-3% 筹码锁定 +2% / >15% 筹码松动 -2%
- 子项3 主力筹码动向：主力净流入占比 ≥3% 吸筹 +3% / ≤-3% 派发 -3%
- 子项4 量能稳定性 CV：≤0.3 沉淀 +2% / >0.8 紊乱 -2%

** 量价6形态分类（`services/pattern.py detect_volume_price_pattern`）**
识别 6 种互斥量价形态（优先级：突破类 > 滞涨/背离类 > 回调类 > 横盘类），作为乘性修正系数（±4%）：
- 放量突破 +4% / 倍量反包 +3% / 缩量回调 +2%
- 放量滞涨 -4% / 量价背离 -3% / 缩量横盘 -1%

**动态阈值（`trend.py _classify_market_regime` + `_get_dynamic_thresholds`）**
按 `market_regime(bull/bear/range) × pattern` 三级优先覆盖 D1/D3/D4 扣分阈值（精确匹配 > regime 默认 > 全局默认）：
- 牛市：放宽乖离惩罚（追高容忍），收紧破位扣分
- 熊市：收紧乖离/回撤档位（追高风险大、回撤容忍收紧）
- 形态特化：放量滞涨/量价背离/缩量横盘扣分加重
- 大盘状态由 sh000001 现价 vs MA20 + 当日涨跌联合判定

**行业中性化（`strategy.py apply_industry_neutralization`）**
对 `calc_stock_score_v2` 输出的 `total` 按行业 P20/P80 分位数做 ±2 后处理调整（见 §9.1 末行），三层调用对齐。单行业样本 <5 不调整。

### 9.2 RPS 相对强度因子（欧奈尔核心，P0）

**定位**：选股胜率提升的 P0 项（性价比最高）。RPS 衡量"个股区间表现强于全市场多少比例的股票"，是欧奈尔 CAN SLIM 体系识别领涨龙头的核心指标。弱市里 RPS 高的票往往率先走强，是"顺势而为"的量化落地。

**算法**
1. 全市场 A 股代码：东方财富 clist（`m:0+t:2,m:1+t:2`）分页拉取（接口单页硬上限 100 条，需翻页合并去重，全市场约 1843 只）。
2. 区间涨幅：腾讯前复权日线（K 线）`param={symbol},day,{START},{END},{limit},qfq`，取区间起点/终点收盘价算 `(c1-c0)/c0`。
   - **为什么不走东方财富 clist 区间参数**：实测 push2delay/push2 的 clist 在带 `k1/k2/k3` 时 `f3` 仍返回当日涨跌幅（接口不支持区间统计），故改用 K 线计算区间涨幅，最可靠。
3. 百分位排名：`RPS = 排名 / (样本数-1) × 100`。RPS 90 = 强于 90% 个股。
4. 多周期：`RPS_PERIODS=[50,120,250]`（月/季/年），主评分用 `RPS_PERIOD_DAYS=120`。

**缓存与调用**
- 盘前/手动触发 `refresh_rps(period_days)`，线程池（`max_workers=10`）并发拉全市场 K 线（1843 只约 30–40 秒），结果写 `rps_cache` 表（主键 `(period, symbol)`，存 `rps` + `interval_change`）。
- 盘中扫描/分析经 `get_rps_map()` 直接读缓存（秒级），无缓存降级中档分 7 分不拖累总分。

**新增接口**
- `GET /api/rps?period_days=120&top_n=50`：RPS 强势股榜（降序前 N，含名称/区间涨幅），供前端 `TabStrategy` 展示。
- `POST /api/rps/refresh?period_days=120`：后台触发全市场预计算，立即返回 accepted，约 30 秒后 `/api/rps` 可查。

**配置项（`app/config.py`）**：`RPS_ENABLED / RPS_PERIOD_DAYS / RPS_PERIODS / RPS_CACHE_TTL / RPS_MIN_SAMPLES / RPS_TOP_N`，以及评分阈值 `STRATEGY_SCORE_THRESHOLDS['rps']`、分值 `STRATEGY_SCORE_VALUES['rps']`、权重 `DEFAULT_WEIGHTS['rps']=1.1`。

### 9.3 风控止损与估值分位过滤（P2a / P2c，2026-07-16）

**P2a 风控止损输出（`services/risk_control.py`）**——为每只被推荐/被查看的股票输出一套"可执行的风控结论"，纯函数（零 IO）可在扫描循环内逐股同步调用，不增加网络请求：

- **止损价 `stop_loss`**：基于当日振幅（波动率代理）动态缩放止损幅度 = `clamp(振幅% × 1.5, 4%, 12%)`；停牌/无振幅数据给中性默认 6%。低波动股止损窄、高波动股止损宽。**V4.2 增强**：止损幅度叠加位置倍率（低位放宽 20%、高位收紧 20%）和龙头倍率（龙头放宽 10%、跟风收紧 10%），实现"低位给更多恢复余地、高位破位快跑"的位置感知止损。
- **买卖点 `buy_sell_points`**（V4.2 位置+龙头感知版）：止盈幅度 = 基础振幅比例 × 位置倍率 × 龙头倍率 × 评分倍率，封顶 15%。位置判定优先 `trend_details.positionPct`（精确年度分位），fallback `base_scores['position']`；龙头判定：连板≥2 / 涨停 / (涨幅≥5%+量比≥2) / (高分+非高位)。输出含 `stockType`（如"低位龙头"）和 `expectationNote`（预期说明文字）。
- **风险等级 `risk_level`**（low / mid / high）：基础由综合评分决定（`<55→high`，`<65→mid`，否则 `low`）；叠加高危信号（估值极端高估 / 龙虎榜净卖出 / 股东户数环比 ≥10% 散户化）至少升 `mid`，高风险不可被降级。
- **仓位建议 `position_suggest`**：low→可重仓(≤80%)，mid→半仓(≤50%)，high→轻仓(≤30%)。
- **一句话 `risk_note`** 直连前端展示。注入点：单股分析端点、full 端点、扫描端点、智能推荐（推荐卡片内嵌"🛡️ 风控建议"区块）。

**P2c 估值分位过滤（`services/valuation.py`，每日 18:10 盘后更新）**：

- 复用 `fundflow._clist` 分页拉全市场 `f9=PE(TTM)` / `f23=PB`，本地 `bisect` 计算百分位（0~100，越高越贵）；亏损股 PE 置 0 不参与排名。落库 `stock_valuation` 表。
- 过滤采用"**双高才高估**"：PE 百分位 ≥90% **且** PB 百分位 ≥90% 才标记 `overvalued`，避免单维度误杀；综合评分 ≥80 的强趋势股豁免（强趋势可容忍高估值）。
- 智能推荐在 top3 选择前跳过 `overvalued 且 score<80` 的票；评分/推荐/扫描均经 `get_valuation_batch()` 注入估值。
- 前端：`TabScan` 第 9 列"风控/估值"徽章（风险等级 + 估值高估提示）；`TabRecommend` 卡片内嵌风控建议区块。

**配置项（`app/config.py`）**：`RISK_CONTROL_STOP_LOSS_MIN/MAX/VOL_MULT/SCORE_HIGH_RISK/SCORE_MID_RISK`、`VALUATION_ENABLED/VALUATION_OVERVALUED_PE_PCT/PB_PCT/VALUATION_UPDATE_TIME`。

## 技术说明

- 前端：Vue 3 + Vite（`client-vue/`），Vite dev 代理到后端 `/api/*` + `/eastmoney/*`；生产由后端挂载 `static/` 构建产物
- 后端：Python + FastAPI（`server/app/main.py`）
  - 腾讯财经API：获取股票实时行情和K线数据
  - 东方财富API：获取热搜榜/板块数据，并通过 FastAPI 路由 `/eastmoney/*` 代理推送给前端（统一使用 `requests + asyncio.to_thread`，避免 `httpx.AsyncClient` 直连 `push2.eastmoney.com` 的 Server disconnected 问题）
  - 人气榜API：`emappdata.eastmoney.com/stockrank/getAllCurrentList`（东方财富股吧真实人气榜，需 `httpx` 库 POST 访问，`requests` 会被服务器拒绝连接）
  - 字节方舟/豆包 API：AI 智能诊断（通过 `server/ai_config.json` 配置，OpenAI 兼容格式）
- 数据库：SQLite（`server/gupiao.db`），使用 `sqlite3` 原生连接 + WAL 模式（定义在 `server/db/database.py`；已从 MySQL 迁移，迁移脚本 `migrate_mysql_to_sqlite.py`）
- 存储：通过 `trend_scan_results` 表持久化，内存缓存加速访问
- 热加载：修改 `config.py` 后自动生效，无需重启

## 评分体系架构

项目内存在**两套独立的评分系统**，各 Tab 页使用的评分来源不同：

| Tab 页 | 评分来源 | 依赖策略权重? |
|--------|---------|:----------:|
| **股票筛选** | `calc_stock_score_v2()` — 10 因子日内评分（含 主力净流入 + 股东人数筹码面 + 行业中性化后处理） | ✅ 是 |
| **智能推荐** | 50% 日内因子 + 50% 趋势因子融合 | ✅ 是 |
| **每日收评**（明日关注） | 三层来源：①智能推荐(50%日内+50%趋势) → ②策略预测(`strategy_predict_records`) → ③趋势扫描高分票。**每只附「明日买入计划」**：开盘条件 + 买入价区间 + 止盈/止损 + 否决清单（盈亏比 ≥1.5） | ✅ 是 |
| **趋势发现** | `is_up_trend()` — 4 维度趋势评分（MA/资金异动/量能/回撤）+ 早期信号层 + // 乘性修正 + 动态阈值 | ❌ 独立体系 |
| **实时行情**（综合评分） | 后端 `calc_stock_score_v2` 注入 `score` 字段，前端 `utils/score.js` 透传展示（权重由后端统一维护） | ✅ 是 |

**策略权重的修改链路**：策略优化页调整权重 → `strategy_factor_weights` 表更新 → 回测自动微调 → 股票筛选/智能推荐/每日收评的评分实时变化。趋势发现和实时行情的评分完全不受策略权重影响。

详见 [评分函数对比与影响链路图](#评分函数对比) 章节。

## 11. P4 优化（2026-07-01）：趋势回测验证闭环 + 资金流并发优化

### 11.1 趋势评分回测验证闭环

**目标**：让趋势评分系统能"回头看自己"，用历史预测 vs 实际涨跌反向校验评分体系的区分度。

**机制**：
1. **预测落库**：每次趋势扫描入选的趋势股，连同当时的修正系数快照（sectorFactor/chipFactor/pattern/marketRegime）落库到 `trend_backtest_records`
2. **N 日回测**：每日 15:30 定时任务扫描所有 `verified_Nd=0` 的历史记录，按 predict_date 分组，并发拉 K 线计算 1/3/5 日累计涨跌
3. **跑赢大盘判定**：`is_correct_Nd = actual_change_Nd > market_change_Nd`（严格大于，基准为上证指数 sh000001）
4. **聚合报告**：按 predict_date 生成 `trend_backtest_reports`，含三周期总胜率 + 分数段（60-70/70-80/80+）胜率
5. **补验机制**：每次回测扫描所有未验证记录（不限日期），避免漏验

**数据库设计**：
- `trend_backtest_records`：三周期字段并存于同一行，UNIQUE(predict_date, symbol)，补验时只 UPDATE 对应周期
- `trend_backtest_reports`：按 predict_date 聚合，三周期统计字段并存，1d 在 D+1 填充、3d 在 D+3、5d 在 D+5

**前端展示**：
- 趋势发现页顶部：昨日回测准确率徽章（1/3/5 日胜率）
- 趋势发现页底部：可折叠回测历史区（三宫格 + 分数段胜率）
- 每张趋势股卡片：昨测✓/✗ 标签

**配置项**（`config.py`）：
| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `SCHEDULE_TREND_BACKTEST_TIME` | '15:30' | 回测定时任务时间 |
| `TREND_BACKTEST_PERIODS` | [1, 3, 5] | 回测周期（天） |
| `TREND_BACKTEST_KLINE_CONCURRENCY` | 5 | 批量拉 K 线并发度 |
| `TREND_BACKTEST_MARKET_SYMBOL` | 'sh000001' | 大盘基准 |
| `TREND_BACKTEST_SCORE_SEGMENTS` | [(60,70),(70,80),(80,101)] | 分数段 |

### 11.2 P4-2 主力净流入并发分页优化

**问题**：`fetch_batch_fund_flow` 原顺序分页拉取 60 页（每页 100 条），耗时约 30s，盘中扫描时拖慢整体节奏。

**优化**：改为分批并发（每批 5 页 + `asyncio.Semaphore(5)`），保留 `requests + asyncio.to_thread` 模式（避免 Server disconnected），预计耗时降至 ~6s。

**约束遵守**：
- HTTP 请求东方财富仍用 `requests + asyncio.to_thread`（非 httpx.AsyncClient）
- 单页 100 条限制不变（push2delay 接口硬限制）
- 字段 `f62`=主力净流入、`f21`=流通市值、`f100`=所属板块
- `_to_float()` 容错 `'-'`/`None`/`''`

### 11.3 市场温度计（2026-07-08 新增）

**目的**：把"每日符合条件的趋势股票数量"作为**市场温度计**长期记录。数量骤降 = 市场转冷、赚钱效应下降，提示**减仓/观望**；数量回升 = 情绪回暖，可择机**加仓**。

**后端数据源**：
- 新增接口 `GET /api/trend/history-counts?days=21`，从 `trend_scan_results` 表按 `scan_date` 分组聚合：
  - `scanned`：当日扫描候选数
  - `result_count`：当日进入趋势池的股票数（即"符合条件"的口径）
  - `avg_score`：当日趋势池平均分
  - `count_80plus` / `count_55plus`：当日高分股数量
- 数据来自每日 09:00–15:00 每 30 分钟一次的自动趋势扫描（全量替换），天然形成时间序列

**前端展示**（趋势发现页顶部可折叠「🌡️ 市场温度计」区）：

| 温度等级 | 条件（当日结果数） | 含义 | 操作建议 |

每行附带**日间变化箭头**（↑+N / ↓-N），一眼看出市场在升温还是降温；最新一天标记「◀今日」。

**2026-07-18 优化**：前端默认每页展示近 **21 个交易日**（约一个月），超出部分翻页，避免历史数据过多时一屏过长；迷你柱状图与数据表格同步按当前页渲染，翻页时柱状图最大值也基于当前页动态缩放。
