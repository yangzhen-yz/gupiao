# 综合优化计划：性能提升 + 策略调优 + 代码清理

## Context

用户反馈系统响应慢（`/api/hot-stocks-scan` 14.5s），要求：
1. **提升所有 tab 页面响应速度** — 经探索发现 6 个 tab 共有 16 处性能瓶颈（串行 await、N+1 查询、冗余请求、无缓存、刷新间隔违规）
2. **对比市面优秀选股策略** — 已搜索市面策略（中长期动量复合打分 40%均线+35%资金+25%斜率、8 核心指标、多因子加权阈值突破等），结合当前 9 因子 + 趋势 4 维度体系，做阈值/权重微调（不新增数据源）
3. **清理无用代码/文件** — 已发现 3 个后端孤儿函数、2 个前端孤儿模块、5+ 处未使用 import、1 个 NameError bug、8+ 处涨停阈值硬编码散落
4. **保证系统流程性** — 前后端评分逻辑分叉（前端 calculateScore vs 后端 calc_stock_score_v2 阈值不一致）需消除

**用户决策**（已通过 AskUserQuestion 确认）：
- 策略方向：仅优化现有因子阈值/权重（不新增基本面/北向资金等数据源）
- 前后端分叉：前端改为纯展示后端 score（删除 calculateScore）
- 性能改动幅度：全面优化（新增轻量端点、加缓存、改刷新间隔、gather 化）

**参考模式**：`/api/hot-stocks-scan`（routes.py:714-765）已验证的"batch=100 + asyncio.gather 批次 + gather(大盘, 资金流向)"范式。

## Part A：性能优化（16 项，按优先级分 4 级）

### A-P0：跨 Tab 全局长尾（最高优先级，一次优化多 Tab 受益）

#### A-：`/api/market-predict` 优化（影响 TabQuote + TabStrategy）
- **文件**：`server/services/market.py:115-200`（`predict_market_risk`）
- **当前**：500 只股票 / batch=20 = 25 次串行 `await fetch_with_retry`，无缓存，每次新建 `httpx.AsyncClient`
- **改动**：
  1. batch_size 20→100（5 批）
  2. `asyncio.gather(*batch_tasks, return_exceptions=True)` 并发
  3. 复用 `get_http_client()` 而非新建 client
  4. 加 60 秒内存缓存（`_market_predict_cache: Dict[str, Tuple[float, Any]]`，key=日期，value=(timestamp, result)）
- **预期**：5-12s → ~1-2s（缓存命中 <10ms）

#### A-：新增 `/api/custom-scan-pool/symbols` 轻量端点（影响 TabQuote + TabScan）
- **文件**：`server/app/api/routes.py`（新增端点，在 `/api/custom-scan-pool` 之后）
- **当前**：TabQuote 和 TabScan 都只需 `symbols` 列表，却触发 `/api/custom-scan-pool`（routes.py:486）的 N 次 K 线计算
- **改动**：
  1. 新增 `GET /api/custom-scan-pool/symbols` → 仅 `load_user_scan_pool()` 返回 `{symbols: [...], count: N}`
  2. 前端 `useStockData.js:loadScanPool` 改调新端点（仅取 symbols）
  3. TabQuote 完全移除 `loadScanPool()` 调用（`scanStockPool` 在 TabQuote 中从未使用）
- **预期**：TabQuote 首屏 -2~4s，TabScan 首屏 -2~4s

### A-P1：单 Tab 高优先级瓶颈

#### A-：TabTrend onMounted 三串行改 Promise.all
- **文件**：`client-vue/src/components/tabs/TabTrend.vue:547-556`
- **当前**：`await loadStockMap()` → `await loadPoolWithIndicators()` → `await loadTrendStocks()` 串行
- **改动**：`await Promise.all([loadStockMap(), loadPoolWithIndicators(), loadTrendStocks()])`；三个 backtest 加载已是非阻塞，保持
- **预期**：首屏 = max(三者) 而非 sum

#### A-：TabTrend `loadYesterdayBacktestRecords` 3 次串行改 Promise.all
- **文件**：`client-vue/src/components/tabs/TabTrend.vue:508-526`
- **当前**：`for` 循环 3 次 `await apiFetch`（最近 3 天）
- **改动**：`Promise.all(dates.map(d => apiFetch(...)))`
- **预期**：3 RTT → 1 RTT

#### A-：TabScan 刷新间隔 5s→30s（符合 project_memory 硬约束）
- **文件**：`client-vue/src/components/tabs/TabScan.vue:113`
- **当前**：`isTradingTime() ? 5000 : ...`（5 秒）
- **改动**：`isTradingTime() ? 30000 : ...`（30 秒）
- **依据**：project_memory.md 明确"Stock scan page refresh interval set to 30 seconds during trading hours"
- **预期**：交易时段请求量降 83%

#### A-P1-4：TabRecommend `/api/daily_recommendations` 历史行情串行改批量
- **文件**：`server/app/api/routes.py:86-142`
- **当前**：每条历史记录（最多 29 条）串行 `await client.get(url)` 拉腾讯行情计算盈亏
- **改动**：所有历史 symbols 合并为 1 次腾讯批量请求（`fetch_with_retry(','.join(all_symbols))` + `parse_tencent_batch_data`），再 join 到记录上
- **预期**：4-9s → ~0.5s

#### A-P1-5：`scan_trend_scan_results` 板块动量预计算串行改 gather
- **文件**：`server/services/trend.py:1421-1430`
- **当前**：`for i in range(0, len, 20): await fetch_with_retry(...)` 串行批量
- **改动**：batch=100 + `asyncio.gather`（参考 `/api/hot-stocks-scan` 模式）
- **预期**：5 RTT → 1 RTT

#### A-P1-6：`process_one_stock` 冗余实时请求消除
- **文件**：`server/services/trend.py:1461-1471` + `server/services/stock.py:298-345`
- **当前**：`get_kline_data` 内部已拉实时行情校准最新 K 线（stock.py:320），`process_one_stock` 又 `fetch_with_retry(symbol)` 拉一次
- **改动**：让 `get_kline_data` 返回 `(kline_data, realtime_data)` 元组；`process_one_stock` 复用 realtime_data，删除冗余请求
- **预期**：~100 只股票 × 200ms / 25 并发 ≈ 1s 冗余消除

## Part B：策略调优（基于市面经验，仅调阈值/权重）

### ：9 因子权重微调（`server/services/strategy.py` + `server/app/config.py`）

参考市面"中长期动量复合打分模型（40%均线+35%资金+25%斜率）"和"8核心指标（基本面4+资金面2+趋势面2）"：

| 因子 | 当前权重 | 调整方向 | 依据 |
|---|---|---|---|
| main_capital_inflow 主力净流入 | 1.0 | → **1.3** | 市面强调"连续3日净流入+占流通市值≥0.5%"，资金面权重应更高 |
| outer_ratio 外盘占比 | 1.0 | → **1.1** | 主动买入意愿是市面"资金面确认"核心 |
| volume_ratio 量比 | 1.0 | 保持 1.0 | 流动性已通过换手率体现 |
| change_percent 涨幅及龙头 | 1.0 | → **1.2** | 龙头战法是市面核心，连板高度应加权 |
| turnover_rate 换手率 | 1.0 | 保持 1.0 | 市面"日均成交额≥5亿"对应，已合理 |
| weibi 委比 | 1.0 | → **0.9** | 委比易被操纵（已检测虚假信号），权重略降 |
| avg_price_deviation 均价偏离 | 1.0 | 保持 1.0 | 中性指标 |
| amplitude 振幅 | 1.0 | → **0.9** | 高振幅既有机会也有风险，市面"日振幅≥8%"偏短线 |
| position 位置评估 | 1.0 | 保持 1.0 | 已含 PE+涨幅组合 |

- **同步**：`STRATEGY_FACTOR_WEIGHTS`（config.py:225-288）默认值更新
- **同步**：前端 score.js 删除 calculateScore 后，权重仅在后端维护（消除分叉）

### ：趋势评分阈值微调（`server/services/trend.py` + `server/app/config.py`）

参考市面"稳步震荡上行 vs 加速拉升"区分：

| 维度 | 当前 | 调整 | 依据 |
|---|---|---|---|
| D2 连板分层 | 5连板=30, 3-4连板=25, 2连板=20, 首板=12 | 保持 | 已符合市面龙头战法 |
| D4 回撤档位 | [(8,20),(12,15),(15,10),(20,5)] | 保持 | 已合理 |
| 加分项"多头排列+低位" | +5 | → **+6** | 市面"中长期均线多头"权重 40%，应加强 |
| 加分项"倍量突破" | +4 | 保持 | 口袋支点市面通用 |
| 加分项"连续阳线" | +3 | → **+4** | 稳步上行市面更推崇 |
| 加分缩放上限 | 18→5 | 改为 20→5 | 配合加分项调整，重新缩放 |

### ：统一涨停阈值常量（消除 8+ 处硬编码 9.8）

**散落位置**（全部改用 `TREND_LIMIT_UP_THRESHOLD`）：
- `server/services/strategy.py:115, 142`
- `server/services/review.py:95, 107`
- `server/services/recommend.py:103`
- `server/services/trend.py:229, 650, 668`（trend.py 内部已部分使用，需补全）

### ：新增"稳步上行 vs 加速拉升"形态区分（参考市面策略）

- **文件**：`server/services/trend.py` 加分项区域（line 403-437 附近）
- **逻辑**：
  - 稳步上行（近20日涨幅 5%-15% + 阳线占比≥60% + 最大单日涨幅<5%）→ +3 分
  - 加速拉升（近5日涨幅≥15% + 量比≥2）→ +1 分（警示透支风险）
- **作用**：市面策略明确"稳步上行趋势延续周期更长，加速拉升易深度调整"
