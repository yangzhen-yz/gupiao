# P2/P3 选股策略优化实现计划

## Context

P0（板块效应+连板梯队）和 P1（主力净流入因子+涨停5档质量）已落地。本计划实现剩余的 P2 和 P3 优化，补齐策略分析报告中识别的 4 个能力缺口：

- **P2-1 筹码结构维度**：当前趋势评分无筹码集中度/松动度评估，无法识别"主力套牢盘压力"和"筹码沉淀"状态
- **P2-2 量价6形态分类**：现有量价检测是散落的二元判定函数，未形成"形态标签"，无法支撑形态驱动的评分修正
- **P3-1 动态阈值**：趋势评分所有阈值静态硬编码，牛市/熊市/不同形态用同一套阈值，无法适应市场环境
- **P3-2 行业中性化**：当前"行业分散"实为概念标签分散（tags[0]），且评分未做行业内相对排名，导致冷门行业的高分股被低估

**用户已确认的决策**：
1. P2-1 筹码用**代理指标方案**（MA成本+换手率+主力净流入+量能CV组合），不接入真实筹码接口
2. P3-2 行业用**东方财富 f100 板块字段**（批量获取，板块作为行业代理）

**核心设计原则**（沿用 P0-1 板块动量的成功模式）：
- P2-1/P2-2 作为**修正系数**叠加到总分，不破坏 trend.py 现有 4 维度 100 分结构
- 三层调用对齐（routes.py / recommend.py / trend.py），复用 P1 的 fund_flow_map 预取注入模式
- 所有新阈值加到 config.py，保留热加载
- 总分公式升级：`total = raw_score * (1 + sector_factor + chip_factor + pattern_factor)`，叠加系数总和上限 0.15

## 实现步骤

### 阶段 1：P2-2 量价6形态分类（新建独立模块，风险最低，是 P3-1 前置依赖）

**新建 `server/services/pattern.py`**：
- 实现 `detect_volume_price_pattern(closes, opens, highs, lows, vols, avg_vol_20, avg_vol_60, latest_idx, amplitude_20d) -> Dict`
- 6 形态优先级互斥：突破类(放量突破/倍量反包) > 滞涨背离类(放量滞涨/量价背离) > 回调类(缩量回调) > 横盘类(缩量横盘)
- 返回 `{'pattern': str, 'factor': float, 'desc': str, 'details': Dict}`
- 阈值从 config.py 读取，与 trend.py 现有 `_check_*` 函数语义对齐但独立实现（避免循环依赖）

**config.py 新增**：
- `TREND_PATTERN_FACTOR` 字典：6形态+none 的修正系数映射（+0.04 ~ -0.04）
- `TREND_PATTERN_*` 阈值常量（倍量比2.0、突破涨幅5%、反包涨幅3%、缩量比0.5、横盘振幅5%、背离量扩1.3）

### 阶段 2：P3-2 数据层（纯增量，不影响现有评分）

**database.py**：
- `init_db()` 中 `stock_basic_info` 表新增 `industry TEXT DEFAULT ""` 列（ALTER TABLE，异常捕获兼容已存在）
- 新增 `load_stock_industry() -> Dict[str, str]` 和 `save_stock_industry(industry_map) -> bool`

**recommend.py `fetch_batch_fund_flow`**：
- clist 请求 fields 增加 `f100`（行业代码）
- 返回值每个 symbol 增加 `'industry': f100值`

### 阶段 3：P2-1 筹码结构修正系数

**config.py 新增**：
- `TREND_CHIP_FACTOR_MAX=0.08` / `TREND_CHIP_FACTOR_MIN=-0.08`
- 4 子项配置：成本压力位（TREND_CHIP_COST_*）、换手率松动度（TREND_CHIP_TURNOVER_*）、主力筹码动向（TREND_CHIP_MAIN_*）、量能稳定性（TREND_CHIP_CV_*）

**trend.py**：
- 新增 `_calc_chip_factor(check_price, ma60_val, ma120_val, turnover_rate, main_inflow_ratio, vol_cv) -> float`
  - 4 子项独立计算后求和，clamp 到 [MIN, MAX]
- `is_up_trend` 签名新增：`turnover_rate: float = 0.0`、`main_inflow_ratio: Optional[float] = None`
- **关键修正**：在函数顶部（数据完整性检查后）初始化 `cv = None`，避免 D3 计算路径跳过时 NameError（原代码 cv 是条件赋值的局部变量）
- 在 sector_factor 计算后（trend.py:423 附近）插入 chip_factor 计算
- 总分公式升级（trend.py:439）：`total_score = round(raw_score * (1 + sector_factor + chip_factor), 1)`
- details 新增 `chipFactor`、`chipCostStatus`、`chipTurnoverStatus`、`chipMainStatus`

### 阶段 4：P3-1 动态阈值（依赖 P2-2 的 pattern）

**config.py 新增**：
- `TREND_DYNAMIC_MARKET_BULL_CHANGE=0.5` / `TREND_DYNAMIC_MARKET_BEAR_CHANGE=-0.5`
- `TREND_DYNAMIC_THRESHOLDS` 字典：`(regime, pattern)` 组合 → 阈值覆盖项
  - 牛市+突破：放宽乖离惩罚阈值（追高容忍）
  - 牛市+放量滞涨：加重扣分
  - 熊市默认：收紧乖离阈值、加重破位扣分(6→8)、收紧回撤档位
  - 量价背离/缩量横盘：加重对应扣分
- `TREND_DYNAMIC_DEFAULTS`：默认阈值（等同原静态值）
- `TREND_TOTAL_FACTOR_CAP=0.15`：修正系数总和上限

**trend.py**：
- 新增 `_classify_market_regime(market_change, market_ma20_val, market_price) -> str`（bull/bear/range）
- 新增 `_get_dynamic_thresholds(market_regime, pattern) -> Dict`（三级优先：精确匹配 > regime默认 > 全局默认）
- `is_up_trend` 签名新增：`market_regime: str = 'range'`、`pattern_info: Optional[Dict] = None`
- 在 D3 量能计算后调用 `detect_volume_price_pattern`（或复用 pattern_info）
- 将原本直接引用 `TREND_D1_DIVERGENCE_PENALTY_TIERS`/`TREND_DEDUCT_VOLUME_SPIKE`/`TREND_D4_DRAWDOWN_TIERS`/`TREND_DEDUCT_MA20_BROKEN`/`TREND_DEDUCT_VOLUME_DIVERGENCE`/`TREND_DEDUCT_AMPLITUDE_FLAT` 的地方改为引用 `dyn_thresh[...]`
- 总分公式最终升级：`total_factor = min(TREND_TOTAL_FACTOR_CAP, sector_factor + chip_factor + pattern_factor)`，`total_score = round(raw_score * (1 + total_factor), 1)`

**scan_trend_scan_results 预计算**：
- 在 market_change 获取后，新增大盘 MA20 预计算（get_kline_data('sh000001')）→ `_classify_market_regime` → `market_regime`
- 在 process_one_stock 的 is_up_trend 调用（trend.py:1336）注入：`turnover_rate`、`main_inflow_ratio`、`market_regime`

### 阶段 5：P3-2 评分集成（改动面最大，放最后统一验证）

## 风险与注意事项

1. **cv 变量 NameError**：trend.py:269 的 cv 是条件赋值，D3 跳过时未定义。必须在 is_up_trend 函数顶部初始化 `cv = None`
2. **修正系数叠加溢出**：三系数叠加最大 +17%，通过 `TREND_TOTAL_FACTOR_CAP=0.15` 钳制，总分再 `min(100, ...)`
3. **行业分位数样本不足**：样本<5 返回 None 不调整；监控"未知"行业占比，>30% 说明 f100 覆盖率不足
4. **f100 返回格式**：可能是行业代码（BK0475）或名称，直接用返回值作分组键，前端展示时映射
5. **动态阈值与回测兼容**：P3-1 改变扣分逻辑，历史回测数据不可比。回测按 regime 分组统计（本次不强制改表结构）
6. **is_up_trend 参数膨胀**：扩展后 11 参数，本次保持兼容不重构，后续可改为 context 字典
7. **DEFAULT_WEIGHTS 无需改**：P3-2 是对现有 9 因子的调整，不新增因子，不触发孤儿过滤
