## 一、目标摘要

P4 是选股打分系统的**自我验证闭环**，让评分系统能"回头看自己"：

1. **趋势评分回测验证闭环**：每次趋势扫描时，将入选的趋势股作为"预测记录"落库；每日 15:30 定时任务对历史预测做 N 日（1/3/5 日）涨跌回测，统计"跑赢大盘"胜率，并按分数段（60-70 / 70-80 / 80+）细分，反向校验评分体系的区分度。
2. **P4-2 主力净流入并发分页优化**：将 `fetch_batch_fund_flow` 的顺序分页（60 页 × 100 条 ≈ 30s）改造为分批并发（每批 5 页 + Semaphore(5)），预计耗时降至 ~6s，消除盘中扫描时资金流向数据"拉取慢导致整体扫描超时"的隐患。

#### A1. 新增表 `trend_backtest_records`（在 init_db 内，第 183 行 stock_concept_tags 表后插入）

**设计要点**：三周期字段并存于同一行，`verified_Nd=0` 表示尚未到验证时点，补验时只 UPDATE 对应周期字段，避免重复 INSERT。

```sql
CREATE TABLE IF NOT EXISTS trend_backtest_records (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    predict_date TEXT NOT NULL,          -- 预测日期（即趋势扫描日期）
    symbol TEXT NOT NULL,
    name TEXT DEFAULT '',
    score INTEGER DEFAULT 0,             -- 入选时的趋势评分
    predict_direction TEXT DEFAULT 'bull', -- 固定 'bull'（趋势池股票均看涨）
    -- 入选时的修正系数快照（便于分析"哪类股票胜率高"）
    sector_factor REAL DEFAULT 0,
    chip_factor REAL DEFAULT 0,
    pattern TEXT DEFAULT '',
    pattern_factor REAL DEFAULT 0,
    market_regime TEXT DEFAULT 'range',
    total_factor REAL DEFAULT 0,
    -- 1 日回测
    verified_1d INTEGER DEFAULT 0,       -- 0=未验证 1=已验证
    actual_change_1d REAL DEFAULT 0,     -- 个股 1 日累计涨跌(%)
    market_change_1d REAL DEFAULT 0,     -- 大盘 1 日涨跌(%)
    is_correct_1d INTEGER DEFAULT 0,     -- 1=跑赢大盘(actual>market)
    verified_at_1d TEXT DEFAULT '',
    -- 3 日回测
    verified_3d INTEGER DEFAULT 0,
    actual_change_3d REAL DEFAULT 0,
    market_change_3d REAL DEFAULT 0,
    is_correct_3d INTEGER DEFAULT 0,
    verified_at_3d TEXT DEFAULT '',
    -- 5 日回测
    verified_5d INTEGER DEFAULT 0,
    actual_change_5d REAL DEFAULT 0,
    market_change_5d REAL DEFAULT 0,
    is_correct_5d INTEGER DEFAULT 0,
    verified_at_5d TEXT DEFAULT '',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,

)
```

### 阶段 B：回测逻辑层（新建 server/services/trend_backtest.py）

#### B1. 主入口 `backtest_trend_predictions() -> Dict`

**流程**：
1. 查询所有 `verified_1d=0 OR verified_3d=0 OR verified_5d=0` 的记录（不限日期，覆盖补验）
2. 按 `predict_date` 分组
3. 对每个 predict_date，判断当前日期是否已过验证时点：
   - D+1：`today > predict_date`（即 predict_date 次日起可验证 1d）
   - D+3：`today >= predict_date + 3 天`
   - D+5：`today >= predict_date + 5 天`
4. 收集所有待验证 symbol，去重后批量并发拉 K 线
5. 对每条记录计算 N 日累计涨跌（`_calc_n_day_change`）
6. 获取大盘指数（sh000001）N 日涨跌
7. 判定 `is_correct = actual_change > market_change`（严格大于）
8. 调用 `update_trend_backtest_verification` 逐条更新
9. 对每个 predict_date 调用 `_generate_trend_backtest_report` 重新聚合报告
10. 返回统计摘要（验证了多少条、胜率多少）

#### B2. 辅助函数

- **`_calc_n_day_change(kline: List[List], predict_date: str, n: int) -> Optional[float]`**
  - 从 K 线数据中找到 predict_date 对应的收盘价 `close[D]`，再取 `close[D+n]`
  - 返回 `(close[D+n] / close[D] - 1) * 100`（百分比涨跌）
  - 若 K 线不足 D+n 天，返回 None（未到验证时点）
  - **边界处理**：predict_date 当天可能非交易日（周末），需向前找到最近的交易日作为 D

- **`_fetch_kline_batch(symbols: List[str], client) -> Dict[str, List[List]]`**
  - 复用 [trend.py:1461 `process_one_stock`](file:///d:/Desktop/guizhou/gupiao/server/services/trend.py) 的 Semaphore + wait_for + gather 模式
  - 并发度限制为 5（回测批量拉取，避免压力过大）
  - 返回 `{symbol: kline_data}` 字典，失败的 symbol 值为 None

- **`_get_market_n_day_change(predict_date: str, n: int) -> Optional[float]`**
  - 拉取 sh000001（上证指数）K 线，计算 D 到 D+n 的涨跌
  - 复用 `_calc_n_day_change` 逻辑

- **`_generate_trend_backtest_report(predict_date: str) -> Dict`**
  - 查该 predict_date 的所有 records
  - 按 period（1d/3d/5d）统计 verified_count / win_count / win_rate
  - 按 score 分段（60-70 / 70-80 / 80+）统计各段 total / win_1d / win_3d / win_5d
  - 调用 `upsert_trend_backtest_report` 落库
  - 返回报告 dict

#### G2. 改造方案

**原结构**（顺序）：
```python
def _sync_fetch():
    out = {}
    for pn in range(1, max_pages + 1):        # 顺序拉 60 页
        r = requests.get(url, params={...pn...}, ...)

result = await asyncio.to_thread(_sync_fetch)  # 整个循环在一个线程内
```

**新结构**（分批并发）：
```python
async def fetch_batch_fund_flow(codes: List[str]) -> Dict[str, Dict]:
    if not codes:
        return {}
    code_set = set(c.lower() for c in codes)

    # 抽取单页拉取为独立同步函数
    def _fetch_page(pn: int) -> List[Dict]:
        url = EASTMONEY_HOT_LIST_API
        headers = {'User-Agent': '...', 'Referer': 'https://quote.eastmoney.com/'}
        params = {
            'fs': 'm:0+t:6,m:0+t:80,m:1+t:2,m:1+t:23,m:0+t:81+s:2048',
            'fields': 'f12,f13,f62,f21,f100',
            'pn': pn, 'pz': 100,
            'fid': 'f62', 'po': 1, 'np': 1, 'fltt': 2, 'invt': 2,
        }
        r = requests.get(url, params=params, headers=headers, timeout=10)
        r.raise_for_status()
        data = r.json()
        return data.get('data', {}).get('diff', []) or []

    # 分批并发：每批 5 页，Semaphore 控并发
    page_size = 100
    max_pages = 60
    batch_size = 5
    sem = asyncio.Semaphore(5)
    found: Dict[str, Dict] = {}
    code_set_found = set()

    def _parse_page(items: List[Dict]):
        def _to_float(v) -> float:
            try:
                return float(v) if v not in (None, '', '-') else 0.0
            except (TypeError, ValueError):
                return 0.0
        for item in items:
            code = item.get('f12', '')
            if not code:
                continue
            market = item.get('f13', 0)
            symbol = ('sh' if market == 1 else 'sz') + code
            if symbol not in code_set or symbol in code_set_found:
                continue
            main_inflow = _to_float(item.get('f62'))
            circ_mv = _to_float(item.get('f21'))
            industry = item.get('f100', '') or ''
            main_ratio = (main_inflow / circ_mv * 100) if circ_mv > 0 else 0.0
            found[symbol] = {
                'main_net_inflow': main_inflow,
                'circ_mv': circ_mv,
                'main_inflow_ratio': main_ratio,
                'industry': industry,
            }
            code_set_found.add(symbol)

    # 并发拉取所有页
    async def _fetch_page_async(pn: int) -> List[Dict]:
        async with sem:
            return await asyncio.to_thread(_fetch_page, pn)

    # 先拉第 1 页确定总数，再分批拉剩余页
    try:
        first_items = await _fetch_page_async(1)
        _parse_page(first_items)
        if len(first_items) < page_size or len(code_set_found) >= len(code_set):
            # 单页就够 或 已找齐
            pass
        else:
            # 分批并发拉 2..max_pages
            remaining_pns = list(range(2, max_pages + 1))
            for i in range(0, len(remaining_pns), batch_size):
                batch_pns = remaining_pns[i:i + batch_size]
                tasks = [_fetch_page_async(pn) for pn in batch_pns]
                results = await asyncio.gather(*tasks, return_exceptions=True)
                stop = False
                for r in results:
                    if isinstance(r, Exception):
                        continue
                    _parse_page(r)
                    if len(r) < page_size:
                        stop = True
                if stop or len(code_set_found) >= len(code_set):
                    break

        print(f'[资金流向] 获取 {len(found)}/{len(codes)} 只股票的主力资金数据')
        return found
    except Exception as e:
        print(f'[资金流向] 批量获取失败（不影响评分，降级为无数据）: {e}')
        return {}
```

**关键改进**：
- 单页拉取抽成 `_fetch_page(pn)` 同步函数
- 用 `asyncio.Semaphore(5)` 控并发（同时最多 5 个 HTTP 请求）
- 每批 5 页用 `asyncio.gather` 并发，批与批之间顺序执行
- 保留 `requests + asyncio.to_thread`（符合 project_memory 约束）
- 提前终止：找齐 codes 或到末页（`len(r) < page_size`）
- 预计耗时：60 页 / 5 并发 × 单页 ~0.5s ≈ **6s**（原 30s）

```markdown
## 11. P4 优化（2026-07-01）：趋势回测验证闭环 + 资金流并发优化

### 11.1 趋势评分回测验证闭环

**目标**：让趋势评分系统能"回头看自己"，用历史预测 vs 实际涨跌反向校验评分体系的区分度。

**机制**：
1. **预测落库**：每次趋势扫描入选的趋势股，连同当时的修正系数快照（sectorFactor/chipFactor/pattern/marketRegime）落库到 `trend_backtest_records`
2. **N 日回测**：每日 15:30 定时任务扫描所有 `verified_Nd=0` 的历史记录，按 predict_date 分组，并发拉 K 线计算 1/3/5 日累计涨跌
3. **跑赢大盘判定**：`is_correct_Nd = actual_change_Nd > market_change_Nd`（严格大于，基准为上证指数 sh000001）
4. **聚合报告**：按 predict_date 生成 `trend_backtest_reports`，含三周期总胜率 + 分数段（60-70/70-80/80+）胜率
5. **补验机制**：每次回测扫描所有未验证记录（不限日期），避免漏验

**数据库设计**：
- `trend_backtest_records`：三周期字段并存于同一行，UNIQUE(predict_date, symbol)，补验时只 UPDATE 对应周期
- `trend_backtest_reports`：按 predict_date 聚合，三周期统计字段并存，1d 在 D+1 填充、3d 在 D+3、5d 在 D+5
```

2. 检查 `trend_backtest_records` 表是否有数据落库（每次扫描后）
3. 检查 `trend_backtest_reports` 表是否有聚合报告
4. 前端刷新趋势发现页，确认徽章/历史区/卡片标签正常显示

### 5.4 边界场景

- **K 线不足 D+N 天**：`_calc_n_day_change` 返回 None，该周期不验证（verified_Nd 保持 0）
- **predict_date 是周末**：趋势扫描只在交易日跑，不会发生
- **批量拉 K 线失败**：单个 symbol 失败不影响其他，该 symbol 该周期不验证
- **回测时无历史记录**：函数返回空统计，不报错
- **资金流接口超时**：降级为空字典（不影响评分）
