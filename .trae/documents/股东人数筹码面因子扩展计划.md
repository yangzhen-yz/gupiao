# 股东人数筹码面因子扩展计划(9 因子 → 10 因子)

## Context(为什么做)

当前评分体系的 9 因子全部聚焦在**日内量价/资金面**(外盘/量比/换手/涨幅/委比/均价偏离/振幅/位置/主力净流入),缺失**筹码面**维度。用户反馈的两个真实痛点:

1. **PE 局限性**:高 PE 不等于差(成长股资金青睐),低 PE 不等于好(价值陷阱资金不进)。当前 position 因子用 PE 绝对值简单二分,会把银行股(PE 5,资金永不介入)打高分、科技龙头(PE 60,资金持续流入)打低分。
2. **股东人数盲区**:股东人数绝对值大(如 100 万户)→ 抛压重难拉升;股东人数环比增加 → 散户化越来越难涨;环比减少 → 筹码集中主力吸筹。这是 A 股筹码面核心指标,当前系统完全空白。

本计划落地**第 10 因子 `holder_structure`(筹码集中度)**,直接回答"资金愿不愿介入"。数据源已验证可用:东方财富 datacenter API `RPT_F10_EH_HOLDERNUM`,月度披露,字段含股东总户数/环比变化率/户均持股。

**架构简化**:股东人数是月度数据(非实时),不需像 fund_flow 那样每次扫描实时拉取。改为定时任务每日拉取最新一期存 DB,评分时从 DB 批量查——更快、接口压力更低。

## 因子设计

### 评分规则(筹码集中度,满分 15,对齐 main_capital_inflow 的 15 分制)

| 条件 | 得分 | 含义 |
|---|---|---|
| 户数 < 3万 且 环比减少 ≥10% | 15 | 高度集中 + 主力吸筹 |
| 户数 < 3万 且 环比减少 | 12 | 小盘 + 筹码趋集中 |
| 户数 3-8万 且 环比减少 ≥5% | 12 | 中小盘 + 筹码集中 |
| 户数 < 8万 且 环比 ±5% 内 | 8 | 中性(筹码稳定) |
| 户数 8-20万 且 环比增加 | 5 | 中大盘 + 散户化 |
| 户数 > 20万 | 3 | 抛压重(不管环比) |
| 环比增加 ≥10% | 2 | 散户化看跌(不论户数) |
| 无数据 | 8 | no_data 中档(避免拖累总分) |

**权重**:1.2(筹码面重要,但数据月度披露有滞后,不能过高。介于 main_capital_inflow 1.3 和 outer_ratio 1.1 之间)

**判断优先级**:先判"环比增加≥10%"(强烈看跌信号优先),再判"户数>20万"(抛压重),最后按户数+环比组合分档。

## 数据源

东方财富 datacenter API(已验证可用):

```
GET https://datacenter-web.eastmoney.com/api/data/v1/get
  ?reportName=RPT_F10_EH_HOLDERNUM
  &columns=ALL
  &filter=(ISNEW="1")              # 只取每只股票最新一期(全市场约5000条)
  &pageNumber={pn}&pageSize=100
  &sortColumns=NOTICE_DATE&sortTypes=-1
Headers: User-Agent, Referer: https://data.eastmoney.com/
```

返回字段(已验证):
- `SECURITY_CODE`:股票代码(纯数字如 300059,需转成 sh/sz 前缀)
- `END_DATE`:截止日期(月末)
- `HOLDER_TOTAL_NUM`:股东总户数
- `HOLDER_TOTAL_NUMCHANGE`:环比增减数
- `TOTAL_NUM_RATIO`:环比变化率%
- `AVG_FREE_SHARES`:户均流通股
- `AVG_HOLD_AMT`:户均持股市值
- `NOTICE_DATE`:公告日期

## 实现步骤

### 1. 新建 `server/services/shareholder.py`(股东人数服务)

参考 `services/recommend.py:12` 的 `fetch_batch_fund_flow` 模式,用 `requests + asyncio.to_thread`(project_memory 硬约束,禁用 httpx 直连东方财富)。

**函数**:
- `async def fetch_all_latest_holder_num() -> Dict[str, Dict]`:全市场分页拉取 ISNEW=1 的最新一期,返回 `{symbol_lower: {holder_num, num_change, ratio, avg_shares, avg_amt, end_date}}`。symbol 转换:6 开头=sh,0/3 开头=sz,8/4 开头=bj(参考 stock.py 现有转换逻辑)。
- `def get_holder_num_batch(symbols: List[str]) -> Dict[str, Dict]`:从 DB 批量查最新一期(`WHERE symbol IN (...)` + 子查询取每只最新),供评分注入用。同步函数,DB 查询快。

### 2. 新建 DB 表 `stock_holder_num`(`server/db/database.py`)

参考现有 `CREATE TABLE IF NOT EXISTS` 模式(database.py 表创建区):

```sql
CREATE TABLE IF NOT EXISTS stock_holder_num (
  symbol TEXT NOT NULL,           -- 小写带前缀 sh600519
  end_date TEXT NOT NULL,         -- 截止日期 YYYY-MM-DD
  holder_total_num INTEGER,       -- 股东总户数
  num_change INTEGER,             -- 环比增减数
  total_num_ratio REAL,           -- 环比变化率%
  avg_free_shares REAL,           -- 户均流通股
  avg_hold_amt REAL,              -- 户均持股市值
  notice_date TEXT,               -- 公告日期
  updated_at TEXT,                -- 更新时间
  PRIMARY KEY (symbol, end_date)
)
```

**CRUD 函数**(参考 load/save_daily_recommendations 模式):
- `save_holder_num_batch(records: List[Dict]) -> bool`:UPSERT(INSERT OR REPLACE)
- `load_holder_num_batch(symbols: List[str]) -> Dict[str, Dict]`:批量查每只股票最新一期

## 风险与注意

1. **数据滞后**:股东人数月度披露,公告日期滞后约1个月。评分用的是"最新已披露"数据,可能滞后1-4周。这通过权重1.2(非1.5+)控制影响。
2. **全市场拉取耗时**:5000只 × 1条 = 5000条,pageSize=100 分页约50页。用 asyncio.gather 并发分批(参考 fetch_batch_fund_flow 的分批并发模式),预计30-60秒完成。每日1次,可接受。
3. **新股/次新股无数据**:上市不足1季度的可能无股东人数数据,走 no_data=8 中档分,不拖累总分。
4. **单股端点补 fund_flow**:步骤6顺带补上单股端点缺失的 fund_flow_data(project_memory 提到的已知差异),这是正向改进,但需确认不破坏 IndexBar 等依赖 `.text()` 的调用方(不会,因为是新增参数,PlainTextResponse 端点不变)。
